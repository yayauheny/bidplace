# 04 · Куда вкладывать время до MVP

**Статус:** рекомендуемая очередь, не новая задача в W4–W7. **Дата:** 2026-11-03. Сначала фактический flow audit на real web/Figma, затем отдельное founder-решение. Коды P0/P1 — приоритет пользы, а не команда Cursor немедленно писать код.

## Правило расстановки приоритетов

1. **Корректность и безопасность обязательного действия** выше всего: ставки, публикация, доступ, приватность, восстановление.
2. **Убираем трение в первой созданной работе и первом посещении** раньше расширения функций.
3. **Качество каждой ключевой сцены** — реальные фото, typography, движения, пустые/ошибочные состояния.
4. **Новые механики engagement** только при проверяемом спросе.
5. Не считать количество закрытых экранов, тестов или PR доказательством ценности.

**Приоритетный вариант пользовательского пути A+C:** укоротить заявку без изменения approval; оставить создание Work после допуска и продажу из опубликованной Work. **Ключевая зависимость:** UI Listing в проверенном main ещё не был подключён; это W4 Task 5, не «простая перестановка готовой кнопки». Варианты B и D — отдельные прототипы.

## P0 — до первого настоящего внешнего пилота

| Пакет | Пользовательский результат | Изменение/объём | Проверить перед закрытием |
| --- | --- | --- | --- |
| Технически завершить W4 core и критичные W6/W7 | Статус ставок/заказов верен, нет тупиков | Доделать уже выбранные critical commerce flows; без нового продукта | Конкурентные ставки, Cron, privacy, контакты, ошибки, real mobile devices |
| Фото/Work без потерь | Автор не теряет результат и понимает media state | Короткий audit текущей фото-подготовки, загрузки, открытия, возврата | Reload, failed upload, image order, pending revision, account switch |
| Return after auth | Человек после login возвращается туда, где возникло намерение | Проверка и исправление только подтверждённых navigation gaps | Guest Add / Save / Bid, stale listing; нет auto-bid |
| Review/status truth | Пользователь понимает «отправлено на модерацию», что дальше | Явная copy/states, устранение confirmed misleading labels | Pending, changed, rejected, approved, no hidden public draft |
| Buyer CTA/readability | Посетитель сразу видит работу, автора, доступность и понятное действие | Аудит public Work, lot block и buy/bid на 390px | Long text, 0 story, sold/reserved, keyboard, reconnect |
| Share basic | Автор хочет и может отправить красивую ссылку | URL+QR+OG validation с реальными preview | Telegram/mobile share, изображение, private leak, CDN/CORS |
| Minimal incident handling | Ошибку и нарушение можно остановить | Действующие модерация/админ, обращение в поддержку, юридическая граница | Abuse report route (ручной канал если нет UI), ban/unlist, rollback |

В рамках P0 отдельно проверять **реальное время модерации и стоимость поддержки**. Нельзя компенсировать недостатки UX тем, что основатель вручную оформляет карточки для всех.

## P1 — сразу после P0, если подтверждён UX-выигрыш

| Предложение | Воздействие | Условный scope | Риски / доработка |
| --- | --- | --- | --- |
| Короткая заявка автора | High | 5 визуальных шагов → 2 коротких блока или эквивалент; optional поля позже | Точный серверный минимум/ревизии/доступ, согласовать Figma |
| Short Work composer (порядок не утверждён) | High | Title/category → фотографии → приватный preview; optional details/story не блокируют. Фото-first отдельно сравнить в Figma | Нельзя ослабить upload/rollback; измерить опыт, а не количество экранов |
| Private preview, похожий на публичную Work | High | Переиспользовать public layout с private data и edit anchors | Ошибочные фото/категория обнаруживаются; доступ только владельцу, без public draft URL |
| Contextual cabinet actions | High | Для опубликованной Work базово «Открыть/Поделиться», «Выставить» — доступное вторичное; первичны исправления/заказ | Не показывать два primary CTA для пересекающихся eligibility/status; проверять published revision |
| First-published success | Medium-high | **Подтверждена публичная опубликованная ревизия** → Open / Share / Next | Не делать visible share лишь по статусу APPROVED, учитывать stale reads и publication state |
| Mobile craft pass | High | 3 основных пути на физическом телефоне | Не смешивать motion polish с глобальным redesign |

**Важное:** эти оценки — экспертные приоритеты, не проверенные трудозатраты. Перемещение первого экрана может оказаться не «два часа», а серьёзной задачей из-за media lifecycle. Перед исполнением запрашивать owner code audit.

## P2 — отдельное исследование/решение после пилота или качественного прототипа

| Идея | Зачем | Gate |
| --- | --- | --- |
| Private Work draft до Seller approval | Снимает бессмысленное ожидание у нового автора | Проверка UX-потери + разрешения/квоты/media/отказы |
| Два входа «Показать» / «Продать» | Не навязывать work-first шаг автору аукциона | Тест кликабельного потока; простое сохранение intent может быть frontend-only, а аукцион не запускается до approval |
| Проактивное заполнение AI | Помочь с текстом/фото/анонсом | Авторское согласие, фактическая точность, time-saving evidence |
| Follow автора/Work или lightweight reminders | Реализовать желание вернуться | Подтверждённое opt-in и интерес к конкретному продолжению |
| Мини-подборки/автор недели | Поддержка discovery и качественного спроса | Настоящий ассортимент, малая ручная стоимость, трафик в другой Work |
| Автопубликация доверенных авторов | Снизить стоимость модерации | Наблюдаемые повторные Work и abuse controls |
| Один streaming/browser-source widget | Естественный fit для живых аукционов | Запрос от стримера, проверка на реальном эфире; без своего видеосервера |

## P3 — сознательно не сейчас

- Мероприятия, мастер-классы, live-видео, платные билеты, сборы и донаты как отдельные доменные модели.
- Предзаказы, ограниченные тиражи и продажа нескольких единиц без inventory/fulfillment решений.
- Свой чат, лента комментариев, постоянный контентный график, соцсеть, глобальные рекомендации и Pinterest-доски.
- New billing/subscription/payment escrow/delivery до соответствующего legal/financial/operations readiness.
- Универсальный Event Engine, масштабная замена схемы Work/Listing.
- Дорогой refactor всех тестов ради чистоты без релизного blocker.
- Красивая анимация всей оболочки, которая не улучшает приоритетные пути и тормозит старые телефоны.

## Почему я не советую сейчас новый масштабный редизайн

Уже есть последовательность из W0–W7, подтверждённые серверные правила, сложный photo workflow и действующая Figma. Перерисовать все экраны до первых наблюдений — риск задержки. Оптимальный scope: **короткая UX-волна с верхними сценариями**, причём перед ней получить:
- end-to-end screen map;
- Figma comparison;
- tap-path по реальному приложению;
- точную dependency matrix по backend/auth/media;
- оценку, где минимальный долговечный fix, где смена контракта.

Не выдавать оценку размера в «днях» без исследованного diff/code owners.

## Acceptance для трёх ключевых путей

### Путь 1 — автор → первая публичная Work

- Человек без консультации понимает, зачем нужен Seller approval.
- Успешно вводит только действительно необходимые данные.
- Видит свою будущую Work до отправки, опциональная история не является блокером.
- Не теряет текст/загруженные фото при Back/reload/ошибках.
- После approval есть понятный URL и действие «поделиться».
- На 390px нет zoom/keyboard/hit-target failures.

### Путь 2 — зритель → Work → Creator

- На холодном mobile web узнаёт предмет и автора, видит статус, не спотыкается о пустые bio.
- Фото и история читаемы, отступы/анимации не мешают просмотру.
- Сохраняет/делится; после auth возвращается к Work.
- Может увидеть другую работу/автора, без навязчивого hard sell.

### Путь 3 — Work → Listing → покупатель → результат

- Автор видит точно утверждаемый предмет, цену/валюту, окно связи; нет «цены за группу», скрытого изменения.
- Гость после auth возвращается на актуальную Work, **ставку автоматически не отправляем**.
- Лот/tick/bid/second chance/order соотносятся с server truth, нет двойного победителя.
- Покупатель понимает, что после заказа контактируется с продавцом и платит вне Bidplace.
- Пользователь видит понятный выход из отмены, отказа, истечения срока и report.
