# 03 · Screen inventory: данные, действия, состояния

**Статус:** вариант UX-спецификации для ревью, **не Figma handoff**. Источники состояния: [UX flows](../design/02-USER-FLOWS-AND-SCREENS.md) §§2,8–10; [RFC](../product/05-MVP-RFC.md) §§8–11; [COMMERCE](../launch/COMMERCE.md) §§2–5; [W4](../launch/waves/W4-commerce-ui.md). Реальное состояние визуальной реализации: [Design status](../design/04-DESIGN-STATUS.md).

## Матрица экранов

| Экран / вход | Цель и главная CTA | Данные / минимальное содержание | Что сократить и как вести себя в состояниях |
| --- | --- | --- | --- |
| Entry «Добавить» | Быстро продолжить намерение | Гость / кандидат / pending / approved / suspended | Не показывать гостю редактор с нерабочей кнопкой; сохранить redirect; loading/error ≠ отсутствует Seller |
| Application · 1 | Представить себя | Фото, имя, страна; **зарегистрированный slug показывается без повторного выбора**, если уже получен в auth | Без отдельного обязательного экрана контактов; проверить исторический DEC-043 о проверяемых данных автора |
| Application · 2 | Обозначить творчество и отправить | Краткое описание, направление, summary того, что отправляется | Подробное био, achievements и public socials — позже; pending с честным сроком только если он известен |
| Application status | Ожидать/исправить | DRAFT/PENDING/CHANGES_REQUESTED/REJECTED/APPROVED/SUSPENDED | Разные CTA; review feedback должен вести к полю; не показывать «автор одобрен» раньше решения |
| Work · begin | Быстро начать Work | Название и категория → существующий серверный draft; фотографии следующим шагом | **Предлагаемый ближний вариант**, сохраняющий текущий порядок; фото-first — UX-гипотеза для прототипа, не утверждённое улучшение |
| Work · essentials | Сделать Work допустимой к moderation | Категория, другие требуемые контрактом данные; optional details | Техника, материал, размеры, год, тираж в раскрываемый раздел, если действительно optional; не путать edition и продаваемое количество |
| Work · story (optional) | Раскрыть работу, только если хочется | Уже существующие блоки HEADING/PARAGRAPH/IMAGE | Не принуждать к контенту, не создавать пустую ошибку; не выдумывать facts при будущем AI |
| Work · private preview | Увидеть качественный результат и отправить | Обложка, автор, название, детали, story, явные модерационные последствия | Максимально близко к public Work, но private; edit anchors; правдивый CTA «Отправить на проверку» |
| My Works / кабинет | Понять текущее следующее действие | Статус Work и отдельный статус Listing/Order | Один primary CTA по состоянию; быстрый reuse; понятные pending/rejected/retry |
| Public Work | Рассмотреть, узнать автора, выбрать действие | Hero, имя, title, optional context, реальные sale conditions | Для portfolio нет искусственной цены; для sale primary CTA; поддержать long names, portrait/landscape, 0 story |
| Public Creator | Познакомиться и посмотреть Works | Имя/фото/обязательные разрешённые поля и Work grid | Профиль с 1 Work законченный; никаких пустых education/awards, verified badge только с действительной проверкой |
| Create Listing (W4 Task 5, UI ещё не подключён в проверенном main) | Выставить реально опубликованную Work | Fixed: currency, price, contact window. Auction: currency, start price, startsAt, endsAt, contact window | Итоговая **сводка + осознанная кнопка в самой форме**, без лишнего отдельного экрана confirm; active listing не редактировать |
| Bid/Buy sheet | Сделать осознанное действие | Серверные актуальные цена, валюта, increment/status, contact window | Один явный confirm действия; **дополнительный confirm только при ставке > 2× минимума** по COMMERCE §4.1; после auth перечитать состояние, не ставить автоматически |
| Deal hub / order | Довести договорённость до результата | Order state, parties' private contacts, deadline, allowed actions | Не обещать оплату/delivery; объяснять отказ, handoff и second chance |
| Share sheet | Сделать красивое распространение | Public URL, QR, при готовности social card | Без четырёх форматов «потому что можем», если блокируют запуск; действующий W5 изменять отдельным DEC |
| Home / Works / discovery | Показать качественные реальные предметы | Небольшие выборки, явные live states и авторы | Никакого «бесконечного соцконтента», автогенерируемых пустых плиток и рейтингов без данных |

## Поля: сейчас и рекомендуемая видимость

### Профиль автора (минимум сервера из RFC §8)

| Поле | Текущий допуск | Предлагаемая видимость | Сохранение privacy |
| --- | --- | --- | --- |
| Фото | Mandatory | Первое знакомство | Аватар не равен документальной верификации |
| Публичное имя | Mandatory | Шаг 1 | Не путать account name и public display |
| User slug | Mandatory в account/URL | **Показывать полученный при регистрации slug**; новый ввод только если отсутствует по текущему auth-контракту | Не запрашивать никнейм второй раз; не использовать неподтверждённый nickname |
| Страна | Mandatory | Шаг 1 | Город остаётся optional |
| Короткое описание | Mandatory для отправки | Шаг 2 | Не требовать профессиональных заслуг |
| Направление/категория | Mandatory для отправки | Шаг 2 | Только доступный и применимый список |
| Социальные ссылки | Optional в RFC/сервере; **исторический DEC-043 ожидает социальную ссылку либо иные публично проверяемые сведения** | После основного пути; перед handoff проверить реальные критерии ручной модерации | Автор не должен неожиданно получать отказ за поле, которое UI назвал необязательным; private email/contacts не публиковать |
| Образование, достижения, практика | Optional | После основного пути | Нет 0 counters или пустых секций |
| Контакты для handoff | Нужны при коммерческих действиях по COMMERCE | Отдельно перед bid/buy или в настройках | **Никогда** не использовать публичные profile socials как private deal contact автоматически |

**Подводный камень:** в ранее принятом DEC-043 и правилах заявки есть проверяемые данные автора. Если упрощение убирает поле, нужное для текущего approval или public policy, сначала проверить точный owner и решить конфликт. Не подменять решение новой версткой.

### Work (approval из product-requirements.ts: title + categoryId + >=1 images)

| Поле | Обязательность перед moderation | Подача |
| --- | --- | --- |
| Название | Обязательное | Сразу с фотографией |
| Категория | Обязательная | Короткий выбор в essentials |
| Основные фото | Мин. одно | Первое содержательное действие с явным save/upload status |
| Обложка/порядок | Управление фото | Рядом с фото, защищённое подтверждение порядка |
| Материал, техника, размеры, год/дата, особенности | Не являются частью базового missingProductApprovalFields; другие проверки и политика могут уточнять | «Добавить детали», проверить фактическую обязанность в текущем контракте |
| «Тираж» | Факт Work | Не превращать в inventory и единицы продажи |
| История HEADING/PARAGRAPH/IMAGE | Необязательная | По желанию, не блокировать перед preview |
| Цена, валюта, условия аукциона | Не поля Work | Только Create Listing после опубликованной approved Work |
| Приватный черновик до Seller approval | Сейчас запрещён в ProductsService.create | Новый permission/media contract, **не разрешён этим документом** |

### Listing (автор и Work approved, COMMERCE §3.1)

| Fixed price | Auction |
| --- | --- |
| priceMinor, currency BYN/RUB | startPriceMinor, currency BYN/RUB |
| startsAt now | startsAt now или будущая дата в разрешённом окне |
| endsAt отсутствует | endsAt = start + 1–14 дней |
| contactWindowHours 1/6/24/48/72 | contactWindowHours 1/6/24/48/72 |
| Без редактирования после публикации | Без редактирования, авторская отмена только до первой ставки |

**Рекомендация UX:** перед созданием показать в **той же форме** конкретную Work, что именно покупают, единицу количества, валюту, цену/старт, срок и контактное окно. Нужна одна понятная final CTA, без универсального второго подтверждения. При существенной ошибке не обещать безопасное «изменить» при уже действующих ставках; предусмотрен cancel/admin process. Не менять саму доменную модель количества.

**Условия review:** наличие статуса APPROVED само по себе не заменяет существование доступной опубликованной ревизии. «Открыть/Поделиться» включаются только по подтверждённому публичному состоянию (не оптимистически после административного клика).

## Матрица состояний и обязательная обратная связь

| Состояние | Видимость | Действие |
| --- | --- | --- |
| Local draft / unsaved image | Только устройство, не серверный факт | «Файл нужно повторно выбрать после закрытия/перезагрузки» когда применимо |
| Product DRAFT | Приватно | Продолжить |
| Product PENDING_REVIEW | Приватна новая ревизия; если уже существует прежняя опубликованная, она остаётся public | Посмотреть отправленную ревизию; не считать PENDING публичной |
| CHANGES_REQUESTED | Приватно | Исправить адресно; не терять медиа |
| APPROVED portfolio + реально доступная опубликованная ревизия | Public | Поделиться, увидеть автора; опционально выставить после server eligibility |
| SCHEDULED listing | Public | Показывать время начала, не принимать преждевременные ставки |
| LIVE listing | Public | Buy или bid, точная цена и состояние |
| ENDED awaiting tick | Public | «Подводим итоги», не выдумывать победителя |
| OFFERED/ACTIVE order | Owner visibility приватная; Work public показывает reserved | Перейти к сделке; контакты только сторонам |
| COMPLETED order | Публичный Work показывает sold | Не утверждать, что платёж прошёл через платформу |
| CANCELLED or FAILED with no active listing | Work как portfolio либо новая разрешённая продажа | Не оставлять старую кнопку Buy |

## Публичная страница и визуальная адаптация

- Проверять 1 Work / 20 Works, 0 bio / длинную bio, 0 story / длинные блоки, широкую и вертикальную обложку, длину названия/имени и локализацию BYN/RUB.
- Не делать слайдер маленьких изображений главнее самой работы; связать preview, Work и share карточки в одну узнаваемую иерархию.
- У автора с одной работой CTA на эту работу заметнее, чем «заполнить профиль на 100%».
- Для продажи показывать доступные действия в контексте, не мешая любителям просто рассматривать творчество.
- Реальный responsive и Figma acceptance отдельно; текущая папка **не заменяет готовые скриншоты и утверждённые значения дизайн-системы**.
