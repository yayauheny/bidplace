# Bidplace · UX-предложения для малого, качественного MVP

**Срез:** 2026-11-03 · **Статус:** Product/UX proposals (НЕ УТВЕРЖДЕНО к реализации) · **Область:** public web, mobile-first.

> Это папка для обсуждения конкретных изменений экранов, порядка действий и набора данных. Она не меняет текущие правила доступа, торгов, дизайн в Figma или объём волны автоматически. Правила в DEC-149/150 и COMMERCE остаются действующими до явного решения основателя. Документация должна пережить будущие итерации: объяснять не только «что хотели», но и «почему», «что проверит гипотезу» и «когда отложенное станет нужно».

## Главный вывод

**Самое ценное улучшение MVP сейчас — убрать трение между намерением автора и достойной публичной страницей, не ослабляя безопасность.** Второй приоритет — безупречный путь зрителя от внешней ссылки к работе, автору, а при наличии продажи — к понятному действию.

Ключевой принцип: **меньше обязательных решений для автора; больше качества на каждом оставшемся шаге**. Не «меньше экранов любой ценой» и не «больше эффектов ради премиальности».

Необходимые сценарии: автор без продажи; повторная публикация; автор с fixed/auction; зритель по ссылке; покупатель со ставкой/заказом.

## Как превращать предложения в работу

1. Определить конкретный сбой/трение и статус: подтверждено кодом, наблюдением или лишь гипотезой.
2. Нарисовать 1–2 варианта пути и проверить на пользователе/реальном телефоне. Для Figma нужны отдельные утверждённые экраны/состояния.
3. Зафиксировать решение основателя; если меняется действующий контракт, append-only DEC с Revises и обновление owner-документов.
4. Проверить влияние на auth, permissions, media, публикацию/ревизии, торговые инварианты, аналитику и юридическую границу.
5. Только затем давать Cursor отдельную ограниченную задачу с review и тестами.

**Защита от дрейфа:** эта папка не становится параллельным COMMERCE, второй Figma и вторым backlog. Не создавать из каждой гипотезы обязательный тикет.

## Статус работы

- **Уже принято ранее:** MVP включает портфолио + fixed price + auction, работа отделена от лота; прямые расчёты; модерация автора и Work; мобильный веб; нет общего ресейла.
- **Рекомендуем к первому UX-ревью:** уменьшить трение заявки, перенести приоритет к фотографиям, улучшить review и навигацию; отточить публичную работу/шаринг.
- **Только после отдельного решения:** разрешить приватный Work до одобрения автора, сквозную подготовку аукциона до одобрения, менять формат W5 и утверждённые анимации.
- **Не делать сейчас:** новый Event Engine, массовый ресейл, донаты, подписки, собственные эфиры, AI-first, социальную ленту.
