## Global Constraints

- Отдельной проверки юристом нет (`DEC-150`, C16): правила площадки
  публикуются решением основателя. Агент не придумывает правил — каждое
  положение ссылается на раздел COMMERCE; чего нет в COMMERCE — вопрос основателю.
- Единственная оставленная пометка `[ЮРИСТ: …]` — срок хранения данных о
  сделках; рабочее значение — черновик 30 дней на ответ на запрос о данных (L3).
- Формулировки COMMERCE §1: bidplace — технологическая площадка, не принимает
  оплату, не участвует в передаче, не гарантирует исполнение; ставка — оферта;
  никакой лексики азартных игр («выигрыш», «лотерея», «ставка на удачу»).
- Аналитика с запуска (`ANALYTICS_WEB_ENABLED=true`): политика описывает
  фактически собираемые поля; риск правового основания принят основателем.
- Сырые исследования (`docs/research/raw/*`) только читать.

## Review Focus

1. Каждое число в «Правилах сделок» совпадает с COMMERCE: срок связи 1/6/24/48/72 ч
   (по умолчанию 24), 2 страйка, 3 брони, жалоба 14 дней, страйк через 72 ч, шаг
   ставки — минимум. → Task 1.
2. Нет обещаний, которых нет в продукте: оплата, доставка, гарантия, возврат
   денег, автоматическое завершение сделки. → Task 1.
3. Политика называет, кому видны контакты (покупатель → автору всегда; автор →
   покупателю по настройке автора) и что они не скрываются после срыва сделки. → Task 2.
4. Нет текста, противоречащего действующим документам `01`–`04` без явной правки
   в них. → Task 2.

## Tasks

### Task 1: «Правила сделок»

**Files:** Create: `docs/legal/site/05-deal-rules.md`.

- [ ] **Шаг 1:** разделы: роли (автор, покупатель, площадка); лот (фиксированная
  цена, аукцион, срок связи, задаёт автор); ставка — оферта, неотменяема, шаг —
  минимум, лидер не повышает сам себя; бронь и лимит 3; заказ и срок связи;
  «Продано» только после подтверждения автора; отказ покупателя и страйк;

  участник — по выбору автора; проданная работа повторно не выставляется;
  страйки, автоблокировка по сигналам и блокировка администратором (ставки
  аннулируются); жалобы 14 дней и три действия администратора; поддержка;
  подтверждение сделки (чек) — не кассовый документ; что bidplace не делает.
- [ ] **Шаг 2:** таблица сверки «положение → раздел COMMERCE» в конце черновика
