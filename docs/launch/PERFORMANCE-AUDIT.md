# Аудит производительности — промпт и порядок работы

Самостоятельная задача для агента. Можно запускать в любой момент (лучше после
W4 и перед W7). Результат — короткий отчёт простыми словами: что мешает
людям сейчас, что можно отложить. Код в этой задаче не меняется; правки —
отдельными задачами у владельцев.

Пример, ради которого это существует: размытие аватара через WebGL заставляло
страницы со множеством карточек зависать. Такие вещи не видны в тестах — только
в браузере на слабом телефоне.

## Промпт

```text
Работай в /Users/yayauheny/projects/bidplace. Прочитай AGENTS.md и
docs/launch/PERFORMANCE-AUDIT.md целиком. Код не меняй. Запусти сервис локально,
пройди §2 и §3, сформируй отчёт по §5. Секреты и .env не читай; если для
запуска не хватает переменной — назови её и остановись.
```

## 1. Запуск

- Node 22, pnpm, Docker. `make install`, затем `make dev` (Postgres в Docker,
  миграции, API `http://localhost:3001/api`, веб `http://localhost:8081`). Файл
  окружения создаёт основатель по образцу примера; агент его не открывает.
- Данные: `ALLOW_DESTRUCTIVE_DEMO_SEED=true pnpm db:reset:demo` (только
  локальная БД): 8 пользователей, 9 опубликованных работ. Для проверки списков
  этого мало — попросить основателя или добавить временные данные скриптом, не коммитить.
- Для цифр скорости — production-сборка: `pnpm build:web` и раздача `dist`
  (dev-Metro медленнее и не показателен). Для поиска лишних запросов и
  перерисовок подходит `make dev`.
- Телефон-эмуляция в Chrome DevTools: устройство 390×844, Network «Slow 4G»,
  CPU «4× slowdown». Отдельно — Safari на настоящем iPhone, если есть.

## 2. Что пройти

Страницы: главная, обзор (работы и авторы, прокрутка 3 страниц), автор,
работа (с историей и лотом), кабинет, черновик работы, сделки, карточка заказа,
настройки. Действия: вход/выход, переход туда-обратно, открытие листов
(шаринг, фильтр, ставка), прокрутка длинных списков.

Для каждой страницы:

| Инструмент | Смотрим |
| --- | --- |
| Network (фильтр Fetch/XHR) | одинаковые запросы дважды за один переход; запросы, которые не нужны этой странице; опрос (`/lot`) — только на открытой работе с живым лотом и не при скрытой вкладке; запросы после ухода со страницы |
| Network (Img) | вес и размер каждой картинки против отрисованного (`naturalWidth` против ширины на экране × DPR); повторная загрузка той же картинки; формат (WebP или PNG) |
| Network (Font) | сколько начертаний грузится; пустой экран до шрифтов |
| Performance (запись 5–10 с прокрутки и открытия листа) | длинные задачи > 50 мс, особенно > 200 мс при нажатии; кадры прокрутки (цель — без провалов ниже ~50 к/с); большие «Paint»/«Composite» от `backdrop-filter`/`filter: blur` |
| Rendering → Paint flashing / Layer borders | перерисовка всей страницы при прокрутке или раз в секунду (таймеры) |
| React DevTools → Profiler, «Highlight updates» | компоненты, перерисовывающиеся без изменения данных (вся страница на каждом тике таймера, весь список при одном лайке) |
| Memory (снимок до и после 10 переходов туда-обратно) | рост без возврата: холсты, Object URL, подписки, таймеры |
| Логи API (`durationMs` в `RequestLoggingInterceptor`) | медленные запросы > 300 мс локально; число SQL-запросов на запрос (временное логирование Prisma, не коммитить) |

## 3. Известные подозреваемые (проверить первыми)

| Где | Почему подозрительно |
| --- | --- |
| Обложки в карточках списков | карточка шириной ~180 px получает `PREVIEW` с длинной стороной 1600 px; `srcset` нет. Возможно, нужен меньший вариант для карточек (решение — у медиа-конвейера) |
| Выборка списков работ и авторов | `portfolioCatalogProductSelect` тянет профиль автора со всеми достижениями и медиа для каждой строки списка |
| Главная | для слота куратора повторно вызываются `getPortfolio` и `getApprovedPublicAuthor` |
| React Query по умолчанию | `staleTime` не задан → каждая загрузка экрана перезапрашивает данные (возврат «назад» = новый запрос). Край кэширует только анонимов на 30 с |
| Шрифты | `useFonts` рисует пустой экран, пока не загрузятся три начертания Inter |
| Размытия | `backdrop-filter: blur(16px)` на каждой карточке (`CoverFrost`), стекло дока и поиска, `filter: blur` в шапке автора; на iOS Safari со множеством карточек — главный кандидат на рывки |
| Таймеры | секундные `setInterval` на экранах входа/подтверждения; таймер аукциона (W4) должен быть один на экран |
| Фото истории | идут через API с чтением байтов из хранилища, без CDN |

## 4. Когда чинить

**Чинить сейчас** (до запуска), если хоть одно:

- страница зависает или прокрутка заметно дёргается на эмуляции телефона;
- нажатие отвечает дольше ~200 мс (длинная задача при действии);
- LCP > 4 с на мобильной эмуляции production-сборки;
- картинка карточки больше 2× нужного размера и тяжелее 300 КБ;
- один и тот же запрос дважды за переход или запросы продолжаются после ухода;
- число SQL-запросов растёт с размером страницы (N+1);
- память растёт с каждым переходом и не возвращается.

**Можно отложить**, если:

- выигрыш < 10 % и пользователь его не заметит;
- лишний запрос не на критическом пути и не повторяется;
- размер бандла, пока LCP в норме;
- перерисовки, которые профилировщик показывает, но кадры не теряются.

**Не делать без замера:** переписывание на другую библиотеку, массовые `memo`,
кэш-слои, отказ от дизайна (размытия) — сначала измерить, потом предложить
вариант, сохраняющий вид (меньший радиус, одна подложка на ряд, статичная
картинка вместо живого размытия).
