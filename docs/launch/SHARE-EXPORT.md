# Карточки для соцсетей и чек — спецификация

Зачем: автор продаёт через свои соцсети. Одна кнопка даёт готовую картинку
работы под формат сторис или поста — с логотипом, ником, ценой и временем до
конца. Тот же механизм рисует чек заказа, который покупатель или автор
пересылает в мессенджер.

Figma: шаринг работы `5091:30095`. Реализация — [W5](waves/W5-share-export.md).

## 1. Форматы

| Формат | Размер, px | Как кладётся фото |
| --- | --- | --- |
| История | 1080 × 1920 | обложка по центру, `cover`; снизу плашка с текстом |
| Публикация | 1080 × 1350 | `cover` |
| Квадрат | 1080 × 1080 | `cover` |
| Оригинал | пропорции фото, длинная сторона 2048 | целиком, без обрезки; плашка поверх нижней части |

Выход: JPEG 0,9 для фото-форматов, PNG для чека.

## 2. Что на карточке

| Слой | Когда |
| --- | --- |
| Фото обложки (опубликованная ревизия) | всегда |
| Затемнение-градиент под текстом | всегда |
| Логотип bidplace | всегда |
| `@handle` автора (slug) и название работы | всегда |
| Цена: «1 250 BYN» или «Ставка 1 250 BYN» | если лот `LIVE` |
| «До конца 2 д 4 ч» | аукцион `LIVE`; значение на момент генерации |
| «Забронировано» / «Продано» | по метке COMMERCE §3.2 |
| Описание (короткое, до 3 строк с многоточием) | переключатель «Добавить описание», по умолчанию выкл. |
| Ссылка `bid.place/…` текстом | всегда (QR — отдельная существующая кнопка) |

Цвета, шрифты, отступы — по Figma; размеры текста задаются в долях ширины
карточки, чтобы один шаблон работал во всех форматах.

## 3. Чек заказа

PNG 1080 × 1350: логотип; «Подтверждение договорённости, не кассовый чек»;
номер заказа; код сделки; дата создания и статус; работа (обложка, название,
автор); сумма и валюта; способ (аукцион / фиксированная цена / предложение);
«bidplace — технологическая площадка, не принимает оплату и не участвует в
передаче». Контактов нет — чек могут переслать третьим лицам.

Доступен участникам в `ACTIVE` и `COMPLETED`. PDF на запуске не делается
(см. [AFTER-WAVES.md](AFTER-WAVES.md)).

## 4. Как рисуем

- На клиенте (веб, где сейчас работает `ShareSheet`), Canvas 2D браузера. Без
  новых зависимостей и без сервера: сервер только отдаёт данные и фото.
- Один рендерер шаблонов: шаблон — список слоёв (`image`, `gradient`, `text`,
  `logo`, `rect`) с координатами в долях; данные подставляются в слои; рендерер
  считает раскладку чистыми функциями и рисует.
- Перед рисованием: `document.fonts.load` для используемых начертаний; фото —
  `crossOrigin = 'anonymous'`. Без CORS на домене медиа холст «отравлен» и
  выгрузка падает — заголовок обязателен (проверка в W5).
- Рисуем только по нажатию. Превью форматов — тот же рендерер в масштабе
  0,25; полноразмерная картинка — только для выбранного формата.
- Отдача: Web Share API с файлом (`navigator.canShare({ files })`) на мобильных
  браузерах; иначе — скачивание. Object URL освобождаются, холсты не держатся в памяти.
