# Ставка

Подтверждение почты сюда не вшивать — сначала [08-CODE.md](./08-CODE.md), потом этот экран.

То же окно ворот — для «Купить» и «предложить свою цену»: гость, код, правила, потом действие. Предложение не мешать с суммой ставки и не подписывать как покупку.

## Порядок

1. «Сделать ставку» на [работе](./04-WORK.md).
2. Гость — вход (только вход или регистрация, **без поля суммы**), возврат на работу, снова кнопка.
3. Почта не подтверждена — окно кода по центру. Почту не вводить.
4. Правила ещё не принимал — короткое окно один раз на аккаунт. Не вместе с суммой. Смысл текста — [13-FOOTER-AND-COMPLAINT.md](./13-FOOTER-AND-COMPLAINT.md).
5. Сумма: работа, минимум, поле, кнопки **+1 / +5 / +100**, подтверждение.
6. Следующие ставки в этой работе — сразу сумма, без кода и правил.

Подтверждение свайпом вправо — пожелание. Нужна и обычная кнопка: ставка необратима.

## Числа

Валюта — белорусский рубль. Первая ставка может равняться стартовой.

Дальше сервер: до 25 — шаг 0,50; до 100 — 1; до 500 — 5; до 1000 — 10; иначе 25. Подсказка на экране не должна врать.

В последние 60 секунд ставка сдвигает конец ещё на 60 секунд, всего не больше 10 минут. Показать спокойно, без хайпа. Таймер на [карточке каталога](./02-WORKS.md) сдвигается так же.

## После ответа

Принято — новая цена, в статусе ставки на странице работы: «вы лидируете».  
Перебили в этот момент: «Ставка уже изменилась. Новая минимальная ставка — …»; статус — перебили.  
История ставок — на блоке аукциона страницы работы, не на карточке каталога.  
Своя работа, администратор, торги не идут — до формы не доходить.

## Ошибки, которые уже есть в продукте

- «Введите сумму ставки в BYN.»
- «Минимальная ставка — {цена}.»
- «Ставка должна увеличиваться на {шаг}.»
- «Не удалось отправить ставку…»

Кнопки +1 / +5 / +100 в макете нужны. Сервер считает другой таблицей — при реализации стыкуем, макет не ждать.
