# Код с почты

Не отдельный «сайт внутри сайта» и не поля внутри формы суммы.

## Как выглядит

**Окно по центру** поверх страницы работы (после нажатия «поставить», «купить» или «предложить цену»). Тот же компонент потом пригодится для других проверок.

На узкой ширине окно может занять почти весь экран — на усмотрение. Смысл тот же: оверлей, не путать с экраном ставки.

## Зачем

Подтвердить почту. Главный сценарий — **перед первым действием**: ставка, «Купить» или предложение цены. Смотреть сайт без кода можно.

## Данные

- email **уже есть** с регистрации. Заново не спрашивать. Показать его (можно коротко, можно только «код отправлен на …»).
- если email вдруг пустой (не должно быть в MVP) — тогда поле email. Не строить основной сценарий вокруг этого.
- 6 цифр;
- живёт 5 минут;
- повтор письма не чаще чем раз в минуту.

## Поток

1. Действие на работе (ставка, «Купить», предложение).  
2. Гость → вход, возврат, снова то же действие.  
3. Почта не подтверждена → **это окно**.  
4. Успех → закрыть окно → правила, если ещё не принимал → сумма или подтверждение покупки / предложения.  
5. Неверный / истёкший код → ошибка в этом же окне, действие ещё не открывается.

Код и сумму на одном кадре не мешать.

## Состояния (обязательны в макете)

Ввод. Отправка. Неверный код (красный текст). Код истёк. Повторить письмо. Успех. Закрыть / отмена (ставка не уходит).

## На усмотрение дизайнера

Клетки vs одно поле. Затемнение фона. Как выглядит на широкой и узкой ширине.
