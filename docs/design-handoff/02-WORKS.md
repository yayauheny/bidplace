# Список работ

Адрес: `/works`  
Сюда же попадает запрос с главной и клик по тегу.

## Цель

Простой список публичных работ. Тап → страница работы.

Публично только одобренные работы одобренных авторов с аукционом: запланирован / идёт / завершён.

## Данные элемента

Те же, что на главной: фото, название (до 200 знаков, 2–3 строки кириллицы), автор, цена, статус, дата конца.

Цена и статус в списке **показываем**.

## Фильтры и сортировка

Для старта достаточно простого списка. Если место есть — не больше необходимого:

- статус: все / идут / запланированы / завершены;
- сортировка: по активности (по умолчанию), новые, скоро завершатся, дешевле, дороже.

Категория, автор, материал, уникальность, год — в продукте умеет API. **Не раздувать первую версию.** Грязные длинные строки материалов как меню — не акцент.

Запрос `q` с главной/тега — тот же список, видно что ищем.

## Пагинация

Сервер отдаёт по 20. Сейчас UI первую страницу и молчит. В макете: конец списка и «ещё», либо явно «показаны первые 20».

## Состояния

Загрузка. Ошибка + повтор. Пусто: «Пока нет работ». Сломанное фото. Длинные названия.

## На усмотрение дизайнера

Вид списка. Не карточка ради карточки — система из [00-BRIEF.md](./00-BRIEF.md).
