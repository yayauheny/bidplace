## Перед кодом

1. Проверь текущую ветку, dirty files, последние коммиты и статусы. Не включай чужие изменения. База этого пакета: `48c38b7` (shared ShareSheet), `c0b2a46` (Work composition). Старые checkbox в плане не доказывают, что компонента нет.
2. Открой соответствующие PNG, `nodes.json` и manifest в `design/figma-handoff/portfolio-phone-v1`, а не только этот промпт. Узлы ищи по ID. Локальный экспорт разрешён как источник; доступ к live Figma не обязателен. Ничего в snapshots и `.pen` не менять. В этой задаче визуальная цель — Figma phone v1; старое Pen-направление не смешивать с ней.
3. Составь короткую таблицу «элемент → source node → размер/отступ/радиус/шрифт/line-height/crop → текущий master → расхождение». Отдели OS status bar макета от контента приложения. Затем критерии успеха и короткий план. Для исправления назови варианты: durable fix / acceptable workaround / hack, выбери durable fix.
4. Если нет необходимого кадра, данных API или решения по поведению — зафиксируй точный пробел и останови только зависимую часть. Не рисуй выдуманный вариант и не называй его Figma parity.

## Границы

- Только область указанного задания; не переписывай приложение. Сначала используй готовые masters. Query/mutation/URL принадлежат экрану или hook; визуальный master получает props.
- Один master на роль, один token layer в `packages/design-tokens`. Нельзя копировать blur, button, field, tab и sheet styles в экран. Для assembly-задачи дефект общего master — отдельный блокер, а не локальная CSS-заплатка.
- Не менять API, схемы, permissions, видимость публикаций, аналитику, порядок изображений, приватность или бизнес-логику ради совпадения картинки.
- Portfolio MVP не включает цены/ставки/корзину/торги/архив, sale status, shipping wizard, process media, OAuth, passwordless code, live search overlay. Нельзя переносить эти элементы из старого макета. `Оплата и доставка` остаётся RFC stub.
- Runtime использует реальные данные/медиа. Для одинаковых с Figma изображений и крайних состояний допустим изолированный QA harness вне production routes; не подменяй API, seed или данные пользователя.
- Не добавлять зависимости, suppressions, `any`, фальшивые controls, глобальные style overrides, refactor соседних экранов. Не лечить визуальный баг добавлением теста на собственную CSS-константу.
- Dock после переходов уже исправлен: не трогать `AppShell`/focused portal без воспроизводимой регрессии. Не возвращать несколько dock-порталов или белую нижнюю подложку.

## Обязательная визуальная приёмка

1. Открой итог в реальном браузере. Сними до/после и эталон для одинакового viewport 390px, масштаба 100%, scroll position и, для точного сравнения, одинакового контента. Сохрани файлы в `artifacts/figma-qa/<task-id>/` и напиши короткий `REPORT.md` со ссылками. Если артефакты игнорируются git, явно укажи это и приложи доступные пути; не ссылайся на несуществующие картинки.
2. Сравни композицию, crop, границы blur, прозрачность, шрифты/переносы, радиусы, отступы и состояния. Для геометрии ориентир — расхождение не больше 1 CSS px на одинаковых данных; отличия сглаживания шрифта объяснять отдельно. Разное содержимое нельзя сравнивать одним процентом pixel diff. Нужны скриншоты и разбор конкретных отличий.
3. Проверь 390, 1024 и 1440px: на широком окне остаётся центрированная колонка 390px, не новый desktop layout. На узком окне и при zoom 200% нет потери действий/текста. Проверь длинные данные, optional/empty, loading, error+retry, missing media — только применимые состояния.
4. Проверь keyboard/focus, Back/Forward, переходы между страницами без reload, reduced motion и доступность последнего содержимого под dock. Для modal — Escape, focus trap и возврат фокуса. Не выдавай просмотр DOM за проверку screen reader.
5. Typecheck, lint без auto-fix, существующие релевантные тесты и web build обязательны. Новые тесты — только на изменённое поведение, минимально; не создавать пачку style snapshots. Технические проверки НЕ заменяют пункт 1–4.
6. Если браузер недоступен или матрица не пройдена, статус `Needs verification`/`Partial`, НЕ `Implemented` для всего экрана и НЕ «готово». Если скриншот отличается, продолжай исправлять в пределах задачи; не завершай по зелёным тестам.
