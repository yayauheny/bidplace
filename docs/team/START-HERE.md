# Bidplace — старт для команды

Это короткая точка входа для нового участника, а не ещё одна копия продуктовой документации. Описание функциональности и актуальные решения живут в документах по ссылкам ниже.

## Что такое Bidplace

Bidplace помогает автору показать себя и свои работы, рассказать их историю и дать аудитории прямой путь к работе. Продажа по фиксированной цене и аукцион — возможные сценарии, но не единственная ценность авторской страницы.

Мы небольшая команда, делаем мобильный продукт и стараемся не усложнять процессы. Точный состав релиза и ограничения см. в [плане запуска](../launch/README.md). Идеи, которые обсуждаем, не означают, что они уже утверждены к разработке.

## Очень простой процесс

1. Обсуждаем идею или проблему в Discord. Нет смысла создавать Issue на каждую мысль.
2. Решили делать — создаём один GitHub Issue (вручную или позднее из Discord). В нём достаточно **что сделать**, **как понять, что готово** и **ссылки на контекст**.
3. Назначаем исполнителя по необходимости. Состояние задачи смотрим в GitHub Projects, а не ведём второй список в Discord.
4. Если есть код — связываем PR с Issue. Закрываем задачу после выполнения; важные продуктовые изменения фиксируем в документации по существующим правилам репозитория.

**Планируемая связка Discord → GitHub:** явная команда `/task` или действие «создать задачу» на сообщении. Бот создаёт Issue и возвращает ссылку в обсуждение. Автоматически превращать все сообщения в задачи не надо. Интеграция пока **не установлена**.

## Важно о приватности

Репозиторий **публичный**: Issues, их описания и комментарии видны посторонним. Не переносите в них приватные переписки, персональные данные собеседников, финансы, договоры, секреты и внутренние заметки встреч. Для связи с Discord передавайте только явно одобренное для публичной публикации описание задачи. В будущем можно выделить приватное место для закрытых задач.
