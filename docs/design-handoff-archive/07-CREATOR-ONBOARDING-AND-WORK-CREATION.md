# Creator onboarding and work creation

Кабинет сейчас — формы заявки, работы и расписания, не витрина «мои работы». Список своих работ в API есть, отдельного экрана списка нет.

---

## Become a creator

Вход: «Создать» (если ещё не одобрен) или «Стать продавцом» / «Заявка продавца» в меню. Адрес `/profile`.

### Steps (создание)

| Шаг | Заголовок | Что заполнить |
|---|---|---|
| 1 | Об авторе | slug, имя, страна, дисциплина, описание, фото |
| 2 | Публичные ссылки | Telegram, Instagram, сайт, «основная ссылка» |
| 3 | Передача и проверка | как связаться после сделки + превью |

Кнопка финала: **«Создать профиль»**. Статус сразу **«На модерации»**. Продавать ещё нельзя.

### Fields

| Поле | Обязательно | Заметки |
|---|---|---|
| URL-slug | да | латиница, цифры, дефис; страница будет `/seller/slug` |
| Имя или название | да | одно поле, не имя+фамилия |
| Страна | да | в форме часто стартовое `BY` |
| Дисциплина | в форме да | на сервере может стать «Автор», если не прислать |
| Фото | да | JPEG/PNG/WebP/GIF, до 5 МБ |
| Короткое описание | да | стиль и работы |
| Хотя бы одна публичная ссылка | да | TG / IG / сайт / основная |
| Способ передачи | да | Telegram, телефон или Instagram |
| Контакт передачи | да | формат: `@username`, `https://t.me/…`, или `+375…` |
| Кто пишет первым | да, есть значение по умолчанию | покупатель автору **или** автор покупателю |

Тип продавца в форме не выбирается: всегда автор. Сценария «инфлюенсер» нет.

После отправки профиль **нельзя править**, пока модератор не вернёт статус «Нужны правки».

Превью шага 3 прямо говорит: публично будут имя, адрес, описание, фото и ссылки; контакт передачи скрыт до сделки.

## Creator status / capability

| Статус | Подпись | Может создавать работы? | Может править профиль? |
|---|---|---|---|
| Нет заявки | — | нет → заявка | — |
| На модерации | На модерации | нет | нет |
| Нужны правки | Нужны правки | нет | да |
| Одобрен | Одобрен | да | нет |
| Отклонён | Отклонён | нет | нет |
| Приостановлен | Приостановлен | нет | нет |

Одобренный автор в шапке видит «Создать» → новая работа, в меню — «Кабинет» (снова `/profile`).

## Create work

Адрес: `/products/new`, потом `/products/[id]`.

Только одобренный автор. После сохранения черновика шаги пишутся в URL.

### Steps

| Шаг | Имя | Можно пустым? |
|---|---|---|
| 1 | О работе | нет, обязательные поля |
| 2 | Изображения | нет, минимум 1 фото |
| 3 | История создания | да, можно пропустить |
| 4 | Проверка | отправка на модерацию |

Кнопка отправки: **«Отправить на модерацию»**.

### Every field

| Поле | Форма | Нужно, чтобы отправили | Публично |
|---|---|---|---|
| Категория | обязательна | да | в каталоге-фильтре да, на странице работы нет |
| Название | обязательно | да | да |
| История предмета | обязательно | да | да |
| Уникальность или тираж | обязательно | да | да |
| Происхождение | обязательно | да | да |
| Город | обязательно | да | да |
| Передача или доставка | обязательно | да | да |
| Техника | необязательно | нет | если есть |
| Материал | необязательно | нет | если есть |
| Размеры | необязательно | нет | если есть |
| Вес | необязательно | нет | в API да, на странице нет |
| Год | необязательно, 0–9999 | нет | если есть |
| Упаковка | необязательно | нет | если есть |
| Состояние | в форме не спрашивают | нет | может показаться, если вдруг есть |
| Введение процесса | шаг 3, необязательно | нет | публичный процесс создания |
| Шаги процесса | до 20, необязательно | нет | публичный процесс создания |
| Фото работы | 1…10 в форме | минимум 1 | галерея |
| Фото шага | необязательно | нет | у шага |

Продуктовый RFC перечисляет технику, материалы, размеры, год как обязательные для лота. **Сервер при отправке их не требует.** Для формы ориентируйтесь на таблицу выше; противоречие — в [11-DISCREPANCIES.md](./11-DISCREPANCIES.md).

Лимит фото: форма говорит 10, сервер по умолчанию **8**. Для макета безопаснее 8 + состояние «лимит исчерпан».

Пока работа на модерации, фото менять нельзя.

## Schedule auction

Отдельный экран `/listings/new` после одобрения работы.

| Поле | Обязательно |
|---|---|
| Работа (только одобренные) | да |
| Начало | да, в будущем в момент «Запланировать» |
| Окончание | да, позже начала |
| Стартовая цена, BYN | да, ≥ 0, до копеек |

Черновик расписания → **«Запланировать размещение»** → публичная страница появляется (если работа уже одобрена).

Валюта только BYN. Скрытого резерва нет. После планирования стартовую цену менять нельзя.

## Preview

Шаг 4 работы — текстовая проверка полей, не полноценный превью публичной страницы.

У автора при создании профиля — компактное превью имени и `@slug`.

Публичная ссылка на работу появляется только после одобрения работы и запланированного аукциона.

## Discrepancies with design docs

- Исследования рисуют «Стать автором»; шапка/меню — «Стать продавцом» / «Создать».
- На десктопе «Создать» видна только одобренному автору; на мобиле «+» виден всем и ведёт на заявку или вход.
- Pen/исследования могут показывать больше шагов превью, чем есть в коде.
- Экрана «мои работы» в UI нет, хотя API список отдаёт (им пользуется экран расписания). Несколько форматов продажи, relist, video upload — не MVP. См. [13-FUTURE-PRODUCT.md](./13-FUTURE-PRODUCT.md).
