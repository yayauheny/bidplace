# Work Detail

Адрес: `/product/[id]`

Дизайнер выбирает композицию. Ниже — группы информации, обязательность, действия и состояния.

---

## Purpose

Показать работу как предмет с историей и дать понятное действие текущей продажи.

Покупатель должен понять, без догадок:

1. что это;
2. кто сделал;
3. почему это ценно / интересно;
4. как это выглядит;
5. можно ли действовать сейчас (ставка);
6. что будет дальше.

Идентичность работы и текущее аукционное действие должны быть сразу понятны. Автор должен быть достижим с этой страницы.

---

## Information groups

Все группы ниже — **данные продукта**. Их не обязательно класть в таком порядке. Три адресных вида в коде (`about` / `creation` / `bids`) — текущая IA реализации, не требование к макету.

### Work identity

| Данные | Обязательно у публичной работы? |
|---|---|
| Название | да |
| История предмета (`story`) | да |
| Статус торгов | да (есть публичный listing) |
| Текущая цена | да |
| Дедлайн или время начала | да |
| Действие | зависит от роли и статуса: «Войти» / «Поставить» / нет ставки |

Стартовая и минимальная ставка есть в данных, пока торги идут. Минимальная ставка должна быть доступна человеку, который ставит. В текущем UI она не везде подписана одинаково.

### Gallery

Упорядоченный список фото работы. Первое фото = обложка discovery и начало галереи.

| Правило | Значение |
|---|---|
| Минимум | 1 фото, иначе работа не публикуется |
| Максимум в форме | 10 |
| Максимум на сервере по умолчанию | **8** файлов, 5 МБ каждый, 40 МБ суммарно |
| Форматы | JPEG, PNG, WebP, GIF |
| Видео в галерее | **NOT FOUND** в MVP |
| Порядок | задаёт автор |
| Сломанное фото | плейсхолдер + «Повторить»; не подменять стоком |

Понятная навигация по нескольким кадрам нужна, потому что у реальных работ будет больше одного фото. Lightbox как отдельный продукт не описан.

Видео процесса — другой слой, DESIGNED_POST_MVP, не часть этой галереи. Отсутствие видео не делает работу неполной. См. [13](./13-FUTURE-PRODUCT.md).

### Creator

Автор достижим со страницы работы.

Сейчас продукт отдаёт на этой странице:

- фото;
- `@slug`;
- полное имя и короткое описание (в одном из блоков текущей реализации);
- ссылка на публичный профиль.

На странице работы **не показываются**: дисциплина, страна, Telegram / Instagram / сайт (они есть в профиле автора).

Follow — не MVP.

### Story of the work

Три разных текста. Не изобретать четвёртое поле «история работы».

| Смысл | Поле | Обязательно |
|---|---|---|
| История предмета: что это и зачем | История (`story`) | да |
| Почему ценно / тираж | Уникальность | да |
| Откуда вещь, кто сделал | Происхождение | да |

Длины: название до ~200 знаков; уникальность до ~240; история — длинный текст (реально — абзацы). В демо история короткая; для макета нужны длинные тексты.

Текущие имена в UI: блок «О работе». Исследование называет главу «История работы». Это одно и то же поле `story` плюс уникальность и происхождение.

### Creation process

Имена в текущем UI: вид «Создание», внутри «История создания».

| Элемент | Обязательно | Лимит |
|---|---|---|
| Введение | нет | до 5000 знаков |
| Шаги по порядку | нет | до 20 |
| У шага: название | да, если шаг есть | до 200 |
| У шага: текст | да, если шаг есть | до 5000 |
| У шага: фото | нет | те же правила картинок |

Пусто: «Автор не добавил историю создания.»

Это не то же самое, что история предмета. Процесс можно оставить пустым — работа всё равно публикуется.

### Facts / specifications

Показывать, только если поле реально есть (кроме обязательных).

| Подпись | Смысл | Обязательно для публикации | На экране сейчас |
|---|---|---|---|
| Техника | как сделано | нет | если заполнено |
| Материал | из чего | нет | если заполнено |
| Размеры | свободная строка | нет | если заполнено |
| Год создания | число | нет | если заполнено |
| Состояние | напр. «Новое» | нет (для авторской вещи не спрашивают) | строка может остаться пустой |
| Уникальность | тираж / единственность | да | да |
| Город | откуда передача | да | да |
| Передача | как забрать | да | да |
| Упаковка | как упакуют | нет | если текст есть |
| Оплата и доставка | **тот же текст, что «Передача»** | — | подпись обещает оплату, которой нет |
| Вес | строка | нет | **в API есть, на странице нет** |
| Категория | справочник | да | **в API есть, на странице нет** |

Честного текста «оплата на платформе не поддерживается» нет.

### Auction and bid history

Один аукцион на работу в публичном окне. Не дублировать вторую форму ставки.

Подробности: [06-AUCTION-AND-BIDDING.md](./06-AUCTION-AND-BIDDING.md).

| Статус | Что нужно понять покупателю |
|---|---|
| Запланированы | стартовая цена, когда начнётся, ставки нет |
| Идут | текущая цена, сколько осталось, можно ли ставить |
| Завершены | торги кончились, ставки нет |
| Ставок ещё нет | история пустая: «Ставок ещё нет.» |

Гость на живых торгах: вход с возвратом.  
Админ: «Администратор не участвует в торгах.»  
Автор своей работы: сервер ставку отклонит. Отдельного состояния «это ваша работа» в UI нет.

Поделиться: копирует ссылку на эту страницу.

### Related works

«Другие работы {имя}»: публичные работы того же автора, без текущей, **максимум 4**. Это не рекомендательный движок.

Пустой список: секцию не показывают, без текста «других работ нет».

Если пользователь победил: доступ к результату заказа.

## States

Поддерживаются сейчас:

- загрузка страницы;
- ошибка загрузки;
- LIVE / SCHEDULED / ENDED;
- нет ставок;
- нет истории создания;
- сломанное фото;
- одно фото / несколько фото;
- гость;
- не подтверждён email;
- не приняты правила;
- админ без ставки;
- ошибка/повтор ставки;
- устаревший минимум;
- поделиться: успех / неудача.

Нет отдельного UI: «это ваша работа»; «продано / не продано» как отдельный статус (только статус торгов и заказ у победителя).

Не MVP на этой странице: follow, сохранить, обязательное видео, купить по фикс. цене, чат.

## Gaps for mockups

- Нужны 1 и много фото.
- Нужна длинная история, не только короткое демо.
- Нужен пример без процесса и с 4–6 шагами процесса.
- Вес и категория есть в данных, на странице не используются.
- Подпись «Оплата и доставка» обещает оплату, которой нет.
- Группировка about / creation / bids vs последовательное чтение — открытый IA-вопрос, не предписание раскладки.
