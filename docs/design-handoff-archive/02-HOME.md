# Home

Адрес: `/`

Дизайнер выбирает композицию. Ниже — цель, данные, действия и состояния.

---

## Purpose

Главная должна:

- представить продукт (это прямые продажи авторских работ, не массовый маркетплейс);
- показать релевантные работы;
- показать авторов;
- дать путь в discovery (все работы, все авторы, поиск);
- дать путь стать автором (существующий вход через Создать / меню; отдельный блок на Главной в текущем продукте **нет**).

Это не бесконечная лента и не полный каталог.

---

## Available data

Сервер (`GET /api/discovery/home`) отдаёт три независимых списка. Отдельного поля featured **нет**.

| Список | Лимит | Сортировка | Ссылка «смотреть все» |
|---|---|---|---|
| Текущие / сильные аукционы (`topAuctions`) | до 3 | по активности | `/works` |
| Авторы (`creators`) | до 4 | как отдаёт home | `/authors` |
| Новые работы (`newWorks`) | до 3 | сначала новые (дата публикации) | `/works` |

Порядок секций в текущем коде: аукционы → авторы → новые работы. Это **не** утверждённое продуктовое требование к чтению; обязательны сами списки и честные пустые состояния.

Одна работа может попасть и в «аукционы», и в «новые». Запрета на дубли нет.

---

## Work item on Home

Данные работы в этих списках (тот же контракт, что в каталоге):

- обложка (первое фото);
- название;
- автор: фото + `@slug` (не полное имя);
- цена: текущая ставка или стартовая, BYN;
- статус торгов: идут / скоро / завершено;
- дата окончания.

Число ставок **не входит** в то, что сейчас показывают в discovery.

Действие: открыть работу.

Нужна ли цена и дедлайн в discovery — продуктовый конфликт (RFC/код показывают; founder-first exploration прячет). См. [11-DISCREPANCIES.md](./11-DISCREPANCIES.md) и [12-OPEN-QUESTIONS.md](./12-OPEN-QUESTIONS.md). Не смешивать слои в одном макете без решения.

## Creator item on Home

Данные:

- портрет;
- полное имя;
- дисциплина (например «Керамика»).

Число работ API отдаёт, в текущем UI **не используется**.

Действие: открыть профиль автора.

## States

| Состояние | Сейчас |
|---|---|
| Загрузка | «Загружаем bidplace…» |
| Ошибка сети | «Не удалось загрузить главную» + Повторить |
| Совсем пусто | «Пока здесь тихо» / «Новые работы и авторы появятся после публикации.» |
| Нет только аукционов | список аукционов не показывают |
| Нет только авторов | список авторов не показывают |
| Нет только новых | список новых не показывают |

Нюанс реализации: полностью пустое состояние завязано на «нет аукционов и нет авторов». Если вдруг будут только новые работы, пустой текст может совпасть с этим списком. Для макета считать честные варианты: нет торгов / нет авторов / нет ничего.

## Gaps

1. Есть ли featured как сущность, или достаточно автоматического топа из 3?
2. Нужен ли манифест платформы (текст не из API)?
3. Нужен ли отдельный вход «стать автором» на Главной, если Создать уже глобальный?
4. Входят ли цена и дедлайн в discovery-представление работы?

Пока вопросы открыты, безопасный макет опирается на **три реальных списка** и честные пустые состояния. Не добавлять follow / save / рекомендации.
