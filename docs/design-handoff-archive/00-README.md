# bidplace — Designer Handoff

Последнее обновление: 2026-08-15  
Для кого: UI/UX дизайнер, без чтения кода.

Этот пакет описывает **реальный продукт** bidplace: что уже работает, что официально задумано, и что пока только исследования. Три слоя никогда не смешиваются.

Пакет задаёт **цель, данные, действия, состояния, приоритет информации и связи навигации**. Внешний вид и композицию экранов выбирает дизайнер. Pen и Figma этим пакетом не заменяются и не правятся.

## What bidplace is

bidplace — площадка **прямых** продаж ценных авторских вещей. Главное слово продукта — **ценность**: авторство, история, ограниченность, честный аукцион.

Это **creator-first**, не универсальный маркетплейс и не вторичный resale.

Продавец — человек, который создал предмет или лично с ним связан. Не перекупщик, не массовый бренд, не доска объявлений.

Покупатель смотрит работу, понимает кто и почему это сделал, и участвует в продаже. Сейчас единственный формат продажи в MVP — timed auction в белорусских рублях. Оплата и передача предмета идут **вне платформы**, после завершения торгов.

Сейчас это закрытый пилот в Беларуси, на русском языке. Продавать можно только после ручного одобрения автора и работы.

## Core journey

```text
автор
→ работа
→ история / авторство / происхождение / ценность
→ форма продажи
→ покупатель
```

Аукцион — **первая и основная** форма продажи, не окончательная идентичность продукта. Другие форматы — см. [13-FUTURE-PRODUCT.md](./13-FUTURE-PRODUCT.md).

Пути открытия (связи, не раскладка):

```text
Главная → Работа
Главная → Автор → Работа
Работы → Работа
Авторы → Автор → Работа
Поиск → Работа или Автор
```

Ставка возможна только на **идущих** торгах, у вошедшего пользователя с подтверждённой почтой и принятыми правилами.

## MVP in one screen

### IN MVP

- Публичный просмотр Главной, Работ, Авторов, Поиска, страницы работы и профиля автора
- Регистрация email + пароль, вход, подтверждение почты, принятие правил
- Заявка стать автором, модерация, создание работы, планирование аукциона
- Ставка в BYN, история ставок, продление дедлайна в последние 60 секунд (soft close)
- После победы: контакты для передачи вне платформы
- Админ: одобрение авторов и работ

### NOT IN MVP

Не показывать на MVP-кадрах как живые контроли:

- Оплата и доставка внутри сервиса
- Чат, внешние уведомления, follow, сохранить работу
- Фиксированная цена, presale/drop, видео процесса как обязательный слой
- Рекомендации, рейтинги, счётчики подписчиков, live-торги
- Несколько валют, скрытый резерв, Buy Now рядом с аукционом

Подробности и классификация: [13-FUTURE-PRODUCT.md](./13-FUTURE-PRODUCT.md).

## Beyond MVP

Кратко. Статусы и механика — только в [13-FUTURE-PRODUCT.md](./13-FUTURE-PRODUCT.md). Не повышать нерешённое до roadmap.

**Направление продукта (CONFIRMED_FUTURE как рамка):** другие creator-led форматы продажи, прежде всего фиксированная цена; позже — подготовка in-platform payments (legal/provider gate).

**Уже в design/product specs как post-MVP (DESIGNED_POST_MVP):** следить за автором; сохранить работу; необязательное видео процесса. Backend нет. На MVP не рисовать.

**Не утверждено (POSSIBLE / UNRESOLVED):** preorder/drop, чат/inbox, внешние уведомления, proxy-ставки, рекомендации, editorial collections, платформенная доставка. Не проектировать как факт.

Система должна оставаться расширяемой (работа ≠ только аукцион; автор ≠ SKU-магазин). Это **не** значит добавлять выключенные будущие кнопки на текущие экраны.

## Source status

### 1. Current implementation

Что реально умеют сайт, API и база **сегодня**. Источник истины для «как сейчас работает».

Примеры: в публичном каталоге цена и дедлайн входят в данные работы; на Главной нет отдельной сущности featured; фильтр по году есть в API, но не в интерфейсе.

### 2. Approved product intent

Что явно решено в продуктовых документах и решениях основателя.

Примеры: MVP — только аукцион в BYN; оплата вне платформы; discovery-маршруты `/`, `/works`, `/authors`, `/search`; wishlist не входит в MVP; аукцион — первый клин, не финальная идентичность.

### 3. Design exploration

Визуальные идеи в `design/creator-first*`, HTML-эскизах и заметках. Это **не** текущее поведение продукта, пока нет отдельного решения основателя.

Примеры: discovery без цены; featured-работа; «Стать автором» как отдельный вход с Главной; follow / save / video как post-MVP контракты без backend.

Если слои расходятся, это записано в [11-DISCREPANCIES.md](./11-DISCREPANCIES.md). Противоречия **не угадываются**.
