# Auction and bidding

Время, цена, статус и победитель принадлежат **серверу**. Интерфейс показывает их, но не считает заново.

---

## Auction lifecycle

Публичные статусы аукциона:

| Статус | Смысл | Ставка |
|---|---|---|
| Запланированы | Начало ещё не наступило. Страницу уже видно | нельзя |
| Идут | Окно торгов открыто | можно, если человек имеет право |
| Завершены | Время вышло. Если была ставка — есть победитель и заказ; если нет — продажа не состоялась | нельзя |

Служебные, не для публичной страницы:

| Статус | Смысл |
|---|---|
| Черновик | Автор ещё не запланировал |
| Отменены | Сняли до старта |

Переходы публичного окна: запланированы → идут → завершены. Назад нельзя.

У одной работы в один момент только один запланированный или идущий аукцион.

---

## What buyer needs to understand

### Запланированы

- Стартовая цена как текущая
- Дата и время начала
- Действия ставки нет
- История обычно пустая

### Идут

- Текущая цена (после первой ставки — сумма последней принятой)
- Сколько осталось до конца
- Действие ставки
- История псевдонимов
- Минимальная следующая ставка — доступна тому, кто ставит

### Завершены

- Торги завершены
- История остаётся
- Победитель в публичной истории — пометка «Лидер» у верхней ставки, не имя человека
- Если этот пользователь выиграл — доступ к заказу

Отдельных статусов «продано» / «не продано» нет. Отсутствие ставок = не продано.

## Bid data

| Данные | Есть? | Комментарий |
|---|---|---|
| Текущая цена | да | сначала равна стартовой |
| Стартовая цена | да в данных | в части текущего UI не подписана отдельно |
| Минимальная следующая | да, только пока торги идут | первая ставка может быть **равна** стартовой |
| Шаг | да, таблица ниже | клиент подсказывает, сервер решает |
| Число ставок | да в данных | в discovery и в панели ставки **не показывается** |
| История | да | псевдоним, сумма, время |
| Настоящее имя / email / id | нет в публичной истории | |

Псевдоним вида **`Bidder a1b2c3`**: стабилен внутри одного аукциона, разный на разных аукционах. В продуктовом тексте раньше был пример `user123` — фактически префикс английский `Bidder`.

Порядок истории: большая сумма выше. Верхняя строка помечается «Лидер».

## Who can bid

| Кто | Может? |
|---|---|
| Гость | нет → вход с возвратом на работу |
| Вошёл, почта не подтверждена | нет → «Подтвердите email» |
| Почта есть, правила не приняты | нет → «Правила участия» |
| Обычный покупатель, торги идут | да |
| Автор этой работы | нет (сервер). Отдельного текста на странице нет |
| Админ | нет. Текст: «Администратор не участвует в торгах.» |
| Запланированные или завершённые торги | нет |

## Bid flow

1. Человек выбирает действие ставки (гость — вход).
2. Если нужно — подтверждает email (код из письма) или принимает правила.
3. Подтверждение ставки: предмет, сумма, серверный минимум, время конца, напоминание что ставка необратима.
4. Ввод суммы в BYN. Подсказка шага.
5. Подтверждение (в текущем UI — жест «Поставить · сумма» или доступная кнопка).
6. Сервер принимает или отклоняет. Если кто-то успел раньше — «Ставка уже изменилась. Новая минимальная ставка — …»
7. Повторная ставка в том же аукционе не требует заново читать правила. Первая ставка в этом аукционе — с явным подтверждением.

Клиент не ставит «на всякий случай»: при ошибке заново читает канонические цену и минимум.

## Error / validation states

Тексты, которые уже есть:

- «Введите сумму ставки в BYN.»
- «Минимальная ставка — {цена}.»
- «Ставка должна увеличиваться на {шаг}.»
- «Минимальная ставка сейчас недоступна. Обновите предмет.»
- «Ставка уже изменилась…»
- «Не удалось отправить ставку…»
- «Не удалось обновить данные торгов…»

Не придумывать клиентский пересчёт шага, расходящийся с таблицей.

---

## Ended auction

1. Сервер закрывает по своему времени.
2. Победитель — высшая ставка; при равенстве — кто раньше.
3. Если ставок не было — аукцион просто завершён, заказа нет.
4. Если есть победитель — создаётся заказ. Стороны видят контакт по правилу «кто пишет первым».
5. Автор отмечает: связались / завершили передачу / срыв.
6. Если победитель пропал — **админ вручную** отменяет заказ и может выбрать следующего. Автозамены нет (направление позже — [13](./13-FUTURE-PRODUCT.md)).

Оплата на платформе не происходит. Экран заказа — статус передачи, не чекаут.

Срок «связаться за 24 часа» хранится у заказа как время, штрафов в MVP нет.

## Timing

- Таймер на экране — отображение, не закон.
- Ставка в последние **60 секунд** отодвигает конец ещё на 60 секунд.
- Суммарно нельзя продлить больше чем на **10 минут** от исходного конца.
- После актуального конца ставка отклоняется.

Это **уже в MVP** (`DEC-039`). Отдельного утверждённого текста «дедлайн продлили» для покупателя нет. Нужно ли его сообщать — продуктовый вопрос, не раскладка. См. [12-OPEN-QUESTIONS.md](./12-OPEN-QUESTIONS.md).

Не возвращать hard close / reserve / proxy / Buy Now без нового решения. См. [13](./13-FUTURE-PRODUCT.md).

## Participation list («Покупки»)

`/me/activity` — только свои ставки. Статусы:

| Код | Подпись сейчас |
|---|---|
| Побеждаете | лидируете |
| Ставка перебита | перебили |
| Выиграли | торги кончились, вы первые |
| Торги завершены | проиграли |
| Ожидаем контакта продавца | заказ, ждут связь |
| Передача завершена | автор закрыл сделку |
| Заказ отменён | отмена |

Админ этого раздела не имеет.
