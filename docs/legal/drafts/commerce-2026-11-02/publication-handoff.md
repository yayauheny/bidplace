2. Перенести утверждённые положения в `docs/legal/site/`: новый `05-deal-rules.md` и правки `01`, `02`, `04`. Согласие `03` и подписи `09` — только если основатель принял рекомендации. До этого переноса `docs/legal/deferred/05-commerce-and-future-features.md` не удалять.
3. Поставить одну редакцию `portfolio-legal-ГГГГ-ММ-ДД` на каждый документ, который API читает вместе. Сейчас это `01`, `02`, `03`, `04`, `06`. Разные редакции или редакция не этого вида дают 503. Правка любого из этих файлов меняет общий хеш, даже если строка редакции та же.
4. Хеш версии: SHA-256 от последовательности `id`, NUL, полный markdown, NUL по документам в порядке массива в `apps/api/src/auth/legal-documents.ts`. Наружу идёт `редакция+` первые 32 hex-символа. Эта версия пишется в согласие. `deal-rules` в массив ещё не входит, поэтому один только новый файл в `site/` хеш не меняет, пока код его не перечислит.
5. Зарегистрировать документ: значение `deal-rules` в `packages/contracts/src/legal.ts`, запись в массиве `legal-documents.ts`, имя файла в `apps/api/scripts/copy-legal.mjs`. Копирование сборки по-прежнему берёт только `docs/legal/site/`, не этот каталог черновиков.
6. Согласие в API и интерфейсе: первая ставка, покупка, принятие предложения и создание лота требуют текущую версию. Без неё отказ `DEAL_RULES_NOT_ACCEPTED`. Проверка допуска остаётся в модуле антифрода. Новая версия снова требует согласия. Регистрационную галочку не расширять.
7. Тесты чтения документов: пакет отдаётся только при общей редакции и без незакрытых квадратных пометок; согласие блокирует новое действие сделки и пропускает его после принятия. Эти тесты не писать, пока тексты не утверждены и не лежат в `site/`.
