# bidplace — дизайн-фундамент

Последнее обновление: 2026-08-10

Статус: **Confirmed; protected**

Этот документ меняется только по прямому решению основателя или назначенного
дизайнера. Для текущего направления визуальная конкретика читается из
`design/pen/bidplace-web-v2.pen`; файл Pen защищён от изменений во время
разработки.

## 1. Образ продукта

bidplace — не универсальная доска объявлений и не криптомаркетплейс. Интерфейс
должен ощущаться как спокойное редакционное пространство для значимых,
авторских, ограниченных или лично связанных предметов, вокруг которых проходит
понятный аукцион.

Ключевые качества:

- работа и её автор важнее интерфейсного chrome;
- фотография и история создают ценность до цены и CTA;
- торги выглядят серьёзно, прозрачно и проверяемо;
- интерфейс тёплый и выразительный, но не декоративный;
- роль пользователя понятна без перегрузки навигации;
- отсутствие данных честно показано, а не заполнено выдуманными метриками.

## 2. Визуальные принципы

### Image first

Основная работа показывается крупно и с корректным кадрированием. Изображение
не служит фоном для нечитаемого текста и не растягивается ради заполнения
контейнера. Missing/error state сохраняет геометрию и не имитирует artwork.

### Editorial hierarchy

Экран строится крупными смысловыми блоками: контекст, работа, автор, действие,
доказательства. Типографика и пространство создают иерархию раньше рамок,
теней и бейджей.

### Warm restraint

Нейтральные тёплые поверхности и спокойный контраст поддерживают изображения.
Цвет действия и статуса используется семантически. Точные значения берутся из
canonical Pen и затем зеркалируются в кодовые tokens.

### Transaction clarity

Текущая ставка, следующий допустимый шаг, deadline, состояние аукциона и
результат действия должны быть различимы без догадок. UI не пересчитывает
серверные auction rules самостоятельно.

### Creator dignity

Публичный профиль и карточка автора показывают только подтверждённые публичные
данные. Нельзя добавлять ratings, sales, followers, awards, verified badges или
другие метрики, которых нет в продуктовых контрактах.

### One visual language

Header, controls, cards, tabs, surfaces и auction actions собираются из общих
примитивов. Route-local копии допустимы только как временная стадия внутри
отдельной ветки и не должны попасть в финальный cutover.

### Quiet motion

Движение объясняет реакцию интерфейса и поддерживает изображение, но не
соревнуется с ним. Hover карточки увеличивает только artwork внутри
обрезанного media viewport; карточка, текст и grid не сдвигаются. Кнопки,
меню, tabs, toast и sticky-переходы используют короткие согласованные
transition tokens. Никаких bounce, бесконечных эффектов, случайных delays и
анимации, мешающей ставке.

### Artwork atmosphere

На product/creator hero допустим мягкий фон, полученный из того же artwork:
увеличенная дублирующая media layer, сильный blur и нейтральная veil-подложка.
Оригинал остаётся резким, текст — контрастным, края — спокойными. Эффект не
подменяет missing state, не требует сторонней картинки и отключается/упрощается
при ограничениях производительности или reduced motion.

## 3. Иерархия визуальных источников

1. `design/pen/bidplace-web-v2.pen` — единственный источник точной композиции,
   геометрии, type, color, radius, spacing и component anatomy.
2. Founder-provided screenshots и локальные архивы Foundation/Gamma —
   утверждённые примеры interaction grammar, blur, atmosphere, media behavior
   и плотности интерфейса, но не product semantics.
3. Живой Avant Arte — проверяемый источник отдельных interaction patterns,
   например clipped image zoom карточки.
4. Текущий production code — источник работающего поведения и contracts, но не
   нового visual target.

Если статический Pen не показывает hover, focus, open/close, sticky transition
или reduced-motion state, разработчик использует точную motion specification
из `03-DESIGN-SYSTEM.md`; он не редактирует Pen и не импровизирует локально.

## 4. Поведение важнее визуального сходства

При переносе макета сохраняются:

- server-authoritative price, minimum bid, deadline и status;
- auth, OTP/rules, seller capability и admin permission gates;
- public/private projection и handoff privacy;
- moderation и lifecycle locks;
- безопасная навигация и текущие поддержанные routes.

Визуальный элемент без поддержанного product/API contract получает один из
статусов: `blocked`, `static presentation`, `hidden until contract`, либо
отдельное product decision. Разработчик не выдумывает поведение.

## 5. Responsive foundation

Desktop frames в Pen — обязательный визуальный target, но не разрешение
уменьшить страницу пропорционально. Для tablet и mobile композиция выводится из
той же иерархии:

- primary content и primary action сохраняют порядок;
- горизонтальные группы могут складываться, но не терять смысл;
- sticky/fixed элементы учитывают safe area и keyboard;
- таблицы получают доступное компактное представление без потери данных;
- minimum touch target — 44×44 px;
- текст не обрезается при системном увеличении и локализации.

Responsive states должны быть согласованы до статуса `Implemented`.

## 6. Accessibility foundation

- Полная keyboard navigation и видимый focus.
- Семантические headings, links, buttons, tabs, menus и tables.
- Не полагаться только на цвет для статусов и ошибок.
- Контраст текста и controls не ниже WCAG AA для соответствующего размера.
- Alt text описывает предмет; декоративные изображения исключаются из
  accessibility tree.
- Countdown не объявляется screen reader каждую секунду.
- Loading, empty, error, disabled, validation и success states доступны без
  pointer-only взаимодействия.
- Reduced motion не мешает получить информацию или завершить ставку.

## 7. Запрещённые подмены

- Изменять Pen, чтобы он совпал с текущим кодом.
- Принимать существующие `modernTokens` за новый visual source.
- Добавлять fake content, fake bids, seller metrics или неподдержанные CTA.
- Делать search/filter/dropdown визуально рабочими без честного contract state.
- Использовать NFT, wallet, blockchain или marketplace semantics.
- Скрывать продуктовый конфликт локальным UI workaround.
