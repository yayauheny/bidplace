# Визуальный и UX-аудит bidplace (portfolio MVP, mobile web 390)

Аудит без правок исходников, зависимостей, документации, Pen/Figma, ветки и коммитов. Смотрел **реально открытые экраны** в изолированном worktree на `390×844`, DPR 2. Скриншот-тул рисует широкое letterbox вокруг колонки 390 — геометрию брал из CDP, не из ширины PNG.

## Контекст и критерии

**HEAD:** `70c5fd52ed306143d62b8352edd45d61943388b9` (`docs: accept mobile discovery launch`)  
**Ветка основного checkout:** `fix/work-final`, грязное дерево. Проверки шли в `/tmp/bidplace-ux-audit-70c5fd5`, не в этих правках.  
**БД:** read-only `bidplace_preview`. Общая `bidplace` не трогалась.  
**Среда:** API `localhost:3015`, Expo web `localhost:8095`. `127.0.0.1` ломает CORS — это среда, не дефект UI.

**Критерии успеха аудита**
- Оценить отрендеренный продукт как цельный editorial UI для автора и посетителя.
- Отделить A (vs утверждённый reference), B (UX/a11y), C (менять сам дизайн — решение основателя).
- Не называть вкусовщину багом; не закрывать расхождения «удобной» версией.
- Не утверждать визуальную проверку экрана, который не открывал.

**Короткий план (выполнен):** канонические docs → skills → изолированная среда 390 → публичные экраны + guest auth → измерения → отчёт.

**Актуальный контракт (перепроверен, не исторический commerce)**
- Portfolio-only, без цены/ставки/корзины: `DEC-082`–`084`, `DEC-087`.
- Приёмка: **только mobile web 390**; широкое окно = центрированная колонка 390.
- Dock: одна капсула **232×64**, Home / Search / Add / Profile (`DEC-088`).
- Карточка работы: **title + author** (`DEC-089`). RFC §6 «краткие факты» — открытая неоднозначность, не баг реализации.
- Home **может** показать «Открытие недели», если есть server-owned pointer (`DEC-086` / RFC §5). Newest/random/hardcoded запрещены.
- Чипы не обещают проверку личности/подлинности/профстатуса (RFC §6, Creator dignity).
- Figma — visual source; **продукт побеждает Figma** в claims и commerce-кадрах (`DEC-085`).
- RFC §4: плавающая панель **не перекрывает контент**.

**Расхождения docs ↔ код ↔ решения (не выбираю сторону)**

| Тема | Документ | Код / приёмка |
|---|---|---|
| «Открытие недели» | `DEC-086`, RFC §5: секция, если pointer есть | `GET /api/portfolio/home` отдаёт `curatorSelection`; `HomeScreen` его не рисует. Status: *Not implemented*. Приёмка 2026-09-13 прошла без секции. |
| Карточка Work | RFC §6: изображение, название, автор, краткие факты | Принятый Figma + `DEC-089`: title + author |
| Заголовок авторов | Figma: «Креативные и проверенные…» | Runtime совпадает с Figma и **ломает RFC §6** |
| Каталог авторов, сорт | RFC: «дата добавления» | UI «По активности»; API `added` = `latest_product_at` (это уже честно зафиксировано в status) |

`scripts/setup` в репозитории нет — side effects setup не запускались.

## Подтверждённые находки

### UX-01 — «Проверенные авторы» в runtime-копирайте  
**Тип:** B (продуктовый claim). Не A: текст совпадает с Figma.  
**Приоритет:** высокий. **Уверенность:** подтверждено.  
**До MVP.** Размер **S**.

**Где:**  
`public-authors-screen.tsx:125` `AppText role="screenTitle"` — «Креативные и проверенные авторы на Bidplace»  
`search-screen.tsx:70` — «Ищите опубликованные работы и проверенных авторов.»

**Проблема:** RFC §6 и Creator dignity запрещают обещать проверку личности, подлинности или профстатуса. Intro авторов при этом честный: `AUTHORS_CATALOG_INTRO` (`portfolio-copy.ts:4–5`) — «Авторы, чьи работы опубликованы на bidplace.» Заголовок и поиск спорят с intro на одном экране.

**Сценарий:** посетитель каталога/поиска читает «проверенные» как гарантию платформы.

**Доказательство:** экран `/authors` и `/search` открыты; строка видна. RFC §6 явно запрещает такой claim. Продукт побеждает Figma.

**Контраргумент:** «так в Figma». Figma — visual source, не владелец claims (`DEC-085`, foundation). Контраргумент не снимает дефект.

**Минимальный durable fix:** один portfolio-safe title/intro в `portfolio-copy.ts` (как уже сделано для intro авторов). Убрать «проверенн*» из Authors title и Search intro.  
**Альтернатива:** оставить Figma-literal — только явное решение основателя (**C**).  
**Упростить:** удалить расхождение title vs intro, не плодить третий слой копирайта.  
**Проверка:** `/authors`, `/search`; grep `проверенн`; существующий `portfolio-copy.spec.ts`.

### UX-02 — Enter в поиске не ищет  
**Тип:** B.  
**Приоритет:** высокий. **Уверенность:** подтверждено.  
**До MVP.** Размер **S**.

**Где:**  
`search-screen.tsx:52–54, 73–84` `submitSearch` только на `FigmaButton.onPress`  
`FilterSearchField.tsx:3–24` — нет `onSubmitEditing` / `returnKeyType`

**Проблема:** запрос живёт в `draftQuery` до кнопки «Найти». Enter на поле ничего не делает. На `/search?q=керамика` попал только после клика «Найти».

**Сценарий:** мобильный web, клавиатура, привычка нажать Enter. Кажется, что поиск сломан.

**Контраргумент:** кнопка «Найти» есть и работает. Для editorial-потока этого мало: одно поле + одна кнопка должны быть одной командой.

**Fix:** `onSubmitEditing` + `returnKeyType="search"` на `FilterSearchField`; на web — `form`/`onSubmit`. Не размазывать submit по экрану.  
**Не делать:** отдельную search-библиотеку.  
**Проверка:** ввод + Enter на `/search`; e2e на submit с клавиатуры.

### UX-03 — Первый экран Work прячет текст вкладки под dock  
**Тип:** B vs RFC §4 («панель не перекрывает контент»). Не A vs 3:4 gallery — галерею не ломать без решения.  
**Приоритет:** высокий. **Уверенность:** подтверждено.  
**До MVP.** Размер **M**.

**Где:** `product-screen.tsx:97–99, 126–192` — 3:4 gallery + title + wrapping chips + `FigmaTabs` + panel; `dockReserve` 96 только в `paddingBottom`.  
Dock: `.figma-dock-items` **232×64 at x=79, y=768**.  
История: первый абзац **y=775, bottom=935**.  
Delivery stub: **y=775, bottom=795**, overlap `true`.

**Проблема:** на 390×844 выбранная вкладка начинается **на 7px ниже верха dock**. Первые строки «История» читаются сквозь капсулу. Весь stub «Оплата и доставка на bidplace пока недоступны.» почти целиком под dock.

**Сценарий:** открыть работу → прочитать замысел или понять, что сделок нет. Без скролла текст не прочитать.

**Evidence:** CDP + скриншоты `page-2026-09-14T12-12-34-280Z.png` (История), `page-2026-09-14T12-13-11-285Z.png` (Оплата). Чипы в две строки (город / материал / техника) поднимают блок так, что tabs садятся на линию dock.

**Контраргумент:** «sticky chrome всегда режет низ, можно проскроллить». RFC запрещает перекрытие. `paddingBottom` спасает конец скролла, не first fold. Посетитель не знает, что под капсулой есть текст.

**Минимальный durable fix (без укорачивания 3:4):** восстановить связь **«первая строка tabpanel ≥ ~12px над верхом dock»**. Сжать измеренный зазор title-block → tabs (`gap: x10` в `product-screen.tsx:176`) и/или держать чипы в одну строку (перенос — цена first fold). Если после сжатия зазоров 3:4 + две строки чипов всё ещё не влезают — это **C**: founder выбирает более короткий first fold, меньше чипов или отдельный scroll-region для gallery.  
**Не делать:** угадывать высоту галереи меньше 3:4.  
**Упростить:** не плодить второй layout Work; чинить ритм одного столбца.  
**Проверка:** `/product/seedAnna001` и `?tab=delivery` на 390×844: `tabpanel.getBoundingClientRect().y + 12 < dock.y`.

Та же геометрия на Author «Об авторе»: практика уходит под dock на первом экране (открывал вкладку ранее). Тот же класс дефекта, тот же fix через shared dock clearance для **первого** текстового блока, не только `paddingBottom`.

**Тип:** B.  
**Приоритет:** средний–высокий. **Уверенность:** подтверждено.

### UX-05 — Нулевой поиск рисует три пустых состояния

**Приоритет:** средний. **Уверенность:** подтверждено.

### UX-06 — Ошибки полей не связаны программно  
**Тип:** B.  
**Приоритет:** средний. **Уверенность:** подтверждено (визуал + DOM).  
**До MVP.** Размер **S**. Shared.

**Где:** `FigmaTextField.tsx:70–72, 123–135` — ошибка в `accessibilityHint`, нет `aria-invalid` / `aria-describedby`. `TextField.tsx:31–36` только проксирует.

**Проблема:** на `/login` невалидный email + пустой пароль: красная обводка и «Введите корректный email» / «Введите пароль» видны. AT не получает invalid+describedby. Нет переноса фокуса на первое поле (для двух полей это слабее, чем ассоциация).

**Контраргумент:** hint иногда читается. Hint не заменяет `aria-invalid`; при повторном фокусе hint смешивается с подсказкой.

**Fix:** `id` на текст ошибки, `aria-describedby`, `aria-invalid={!!error}`. Видимый текст уже есть — не дублировать.  
**Не делать:** ослаблять zod.  
**Проверка:** login submit → input `[aria-invalid=true]` указывает на текст ошибки.

### UX-10 — Zoom 200% обрезает dock и режет title карточки  
**Тип:** B.  
**Приоритет:** средний. **Уверенность:** подтверждено для метода ниже.  
**До MVP** желательно; если нет времени — сразу после, но не «опционально». Размер **M**.

**Метод:** `document.documentElement.style.zoom = '200%'` на `/`. Это CSS zoom, не Ctrl± браузера и не OS.

**Что видно:** `page-2026-09-14T12-14-16-914Z.png` — капсула обрезана (Профиль вне колонки; dock width 195 at x=0). Title карточки схлопнулся до «Композиция». Горизонтального `scrollWidth` overflow нет (`overflowX: 0`) — контент **клипается**, не скроллится.

**Контраргумент:** CSS zoom ≠ browser zoom. Возможны отличия. Клип фиксированной 232-капсулы при увеличении всё равно риск.

**Fix:** dock и cover title должны переживать 200%: капсула не клипается; title карточки переносится (2 строки), не обрезается посередине слова без доступа к полному имени (имя есть в a11y label — визуально нет). Не декоративный blur.  
**Проверка:** Home и Work на 390 с zoom 200% — 4 иконки dock видны; title карточки читается целиком или аккуратно в 2 строки.

7. **Имя Filter dialog + inert фона.**
