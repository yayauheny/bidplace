# WAVE W1 — One sheet mechanism (`AppDialog`) and Safe Area for sheets

Model: sol, effort medium. Base: the accepted result of W0 (branch `ds/w1-sheet`).

## Why

Bottom sheets are implemented three different ways. `FilterSheet` uses a React Native `Modal` with its own dimmer inside it, so the dimmer slides up together with the panel; its height is hand-computed (`height * 0.85`, `- 150`); `AppDialog` already animates backdrop and panel independently; `ExitConfirmDialog` adds a second focus trap on top of the dialog's own. The sheet bottom padding ignores the device Safe Area, which breaks the PWA layout. One sheet mechanism, one bottom-space rule.

Figma facts (live file `pAPQo6cADmG5XzVmBX76EE`, section "05 · Фильтры и сортировка · Mobile", node `7008:1756`): sheet frame width 390, content inset 20 on both sides, drag handle 36x4, bottom padding **40** in the filter sheet and **20** in the contact sheet ("10 · Избранное"). Sheet visuals in code stay as they are; only the mechanism and the bottom space change.

## Do

1. **`FilterSheet` (and `FilterSortSheet`, which wraps the same panel)** -> render inside `AppDialog` with `presentation="sheet"`. Compact and full variants use the same mechanism. Remove the React Native `Modal`, the inner `OverlayDimmer` usage, the `animationType` switch and the arithmetic height math. All consumers keep their current props and behavior (close on Escape, outside click and the close button; focus returns to the opener; same `accessibilityLabel` / title). `rg -n "FilterSheet" apps/mobile/src` first and list every consumer in the report.
2. **`AppDialog`**:
   - Add a `bottomSpace` prop for sheets: `20 | 40`, default 20. Sheet bottom padding = `max(bottomSpace, insets.bottom)`, using `useSafeAreaInsets` from `react-native-safe-area-context` (already installed). Put the calculation in one small pure function in the dialog's style module (next to `app-dialog-host-style.ts`) so it can be unit-tested.
   - Position the sheet host with flex/CSS (`alignItems: 'center'`, `width: '100%'`, `maxWidth: layout.sheetMax`) instead of the JS `left/right` calculation from `useWindowDimensions` in `app-dialog-host-style.ts`. Add `layout.sheetMax = 390` to `packages/design-tokens/src/tokens.ts` (a sheet stays a bottom sheet at any viewport width; on wide viewports it floats, with the radius it has today). Both `AppDialog.tsx` and `layout/AuthViewport.tsx` currently read the phone width for this: switch those reads to `layout.sheetMax`. **Do not otherwise change `AuthViewport`.**
3. **`ExitConfirmDialog`**: remove its own `useDismissibleOverlay` / `useOverlayFocusTrap` usage so there is one focus trap (the dialog primitive's). Behavior stays: Escape, outside click, focus return, labels.
4. **Delete** `components/layout/OverlayHost.tsx` (verify with `rg` that nothing imports it).
5. **Web viewport:** add `apps/mobile/src/app/+html.tsx` (Expo Router web root) with `viewport-fit=cover` so `env(safe-area-inset-*)` is not 0 in a PWA. First check whether a root HTML or viewport meta is already configured (`rg -n "viewport" apps/mobile`); if one exists, change that one instead of adding a file.
6. **Tests:**
   - One unit test for the pure bottom-space function (`max` of `bottomSpace` and inset, for 20/40 and insets 0/34). Put it in the existing owner spec for the dialog styles if there is one, otherwise next to the module.
   - Extend an existing Playwright spec (for example `share-sheet-motion.spec.ts`, or the spec that owns the filter sheet) with one assertion: when the compact filter sheet opens, the backdrop does not translate in Y (only the panel does). No new spec file.

## Boundaries

- `SearchOverlay*`, `OverlayDimmer` (still used by the search overlay layer), `use-dismissible-overlay`, `use-overlay-focus-trap` and their specs **stay**; their remaining consumer is the search overlay.
- `AuthViewport.tsx`: only the single `sheetMax` read. No rewrite.
- Native paths are not verified and not claimed. No new dependency. No restyling of sheets.

- `OverlayHost` does not exist; `rg -n "OverlayHost" apps/mobile/src` -> empty.

- Playwright chromium (or "not run: reason"): `share-sheet-motion`, `author-static-header`, `creator-profile`, `auth-layout`, `search-overlay`, plus the new assertion.

## Stop

The sheet needs a new primitive or dependency; focus handling regresses in `SearchOverlay`; a consumer relies on `FilterSheet` rendering outside `AppDialog` for a reason you cannot remove.
