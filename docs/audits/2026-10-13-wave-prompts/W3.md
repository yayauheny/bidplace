# WAVE W3 — Token diet, Figma-accurate control sizes, guard rails

Model: terra, effort medium. Base: the accepted result of W2 (branch `ds/w3-tokens`). Many files, little logic; verify with scripts and tests.

## Why

`packages/design-tokens/src/tokens.ts` has ~400 leaf tokens; about 134 are never read; `figmaTokens` is a pure alias of `designTokens` (`export const figmaTokens = designTokens`) read in ~47 files, which suggests a second system that does not exist. `figma-button.ts` carries its own colors/typography/sizes named after screens and computes height as `(paddingY + strokeWidth) * 2 + lineHeight`, which produces 43 / 47 / 51 / 55 instead of the designed 42 / 46 / 50 / 54. Nothing in the lint setup stops the same duplication from coming back.

**Figma rule (verified in the live file `pAPQo6cADmG5XzVmBX76EE`):** controls have a 0.5 px _outside_ stroke, so Figma's bounds are 1 px larger than the designed size. Designed size = Figma bounds - 1. Examples: sheet action button node `7008:1868` has padding 14 + line 26 = **54** (bounds 55; radius 80; `Inter Medium 14/26`, letter-spacing -0.28); text field node `7021:2938` has padding 13 + line 24 = **50** (bounds 51; radius 18; `Inter Regular 14/24`). In React Native the border is drawn _inside_ the box, so a size is set as an explicit `height` and the text is centered; there is no `padding + stroke` arithmetic.

## Do

1. **Dead tokens.** Write a throw-away script in `/tmp` (not in the repo) that lists every leaf of `designTokens` and counts reads (`designTokens.a.b`, destructuring, `figmaTokens.*`) in `apps/mobile/src` and `packages` excluding spec files. Delete tokens with 0 reads. Attach the command and the deleted list (names only) to the report. **Do not delete** a token that is read dynamically (`AppText role=...`, `designTokens[name]`, spread of a group); list those as "kept: dynamic".
2. **Alias.** Replace every `figmaTokens` with `designTokens` (mechanical), then delete the alias in `tokens.ts`.
3. **Control sizes (by the Figma rule above).**
   - `size.input` 51 -> **50**.
   - `packages/design-tokens/src/figma-button.ts`: sizes `sm 42`, `md 46`, `lg 50`, `xl 54` (current defaults: `matrix` 43 -> 42; `navigation`/`event` 47 -> 46; `auth` 51 -> 50, which is 24 of 30 explicit `size=` usages; `exitConfirm` 55 -> 54). Height is an explicit `height` token; remove the stroke-width term from the height formula. Keep the existing size _names_ if renaming costs more than changing numbers.
   - Remove duplicated colors/typography in `figma-button.ts` that already exist in `designTokens` (for example `#FFFFFF #565656 #121212 #949494 #F3F3F3 #2A2A2A #D1D1D1` and the Inter 600 14/26 typography duplicating `authButton`/`authButtonStrong`) by referencing the existing tokens. The button text style in Figma is `Inter Medium 14/26` with letter-spacing -0.28: if the existing typography token differs from that, report the difference, do not silently pick one.
   - Other odd heights (`auth.codeCellHeight 61`, `auth.passwordHeight 51`, `auth.screenPasswordHeight 53`, `size.filterSortBar 43`, `size.choiceChipRemovable 39`, `auth.resendHeight 51`, `auth.actionHeight 51`, `auth.suggestionHeight 37`, `auth.exitActionHeight 55`): change by the same rule **only if** you can name the Figma node that shows the bounds; otherwise leave unchanged and list them in the report as "needs a node".
   - Delete `useCssBorderBox` (or its equivalent) if nothing needs it once sizes are explicit.
   - Update tests that encode the old numbers to the new numbers; prefer asserting relations (`height === designTokens.control.md`) over repeating a literal. List each changed expectation in the report with the reason (intentional Figma-accurate size change).
4. **Z-index.** `apps/mobile/global.css` dock `z-index` should come from the existing `layer` token, not a literal duplicated in CSS.
5. **Guard rails (ESLint built-ins only, no custom plugin).** In the mobile ESLint config add:
   - `no-restricted-imports`: `expo-router/build/*`; `lucide-react-native`; `Modal`, `TouchableOpacity`, `TouchableHighlight` from `react-native`.
   - `no-restricted-syntax`: a hex color literal (string matching `^#[0-9a-fA-F]{3,8}$`) outside `packages/design-tokens` and the brand SVG file(s) (use `overrides` for those paths).
     Fix every violation the new rules reveal (do not disable). If a violation needs a real design decision (for example a hex used for a decorative SVG), list it and add a narrow, commented exception for that file only.
     **Do not** enable `react-hooks` or `jsx-no-leaked-render` in this wave.
6. **One spec (~40 lines)** in the existing token/owner test location (find it with `rg -l "designTokens" --glob "*.spec.ts"`): (a) no token with zero reads, (b) no odd or fractional number in `space`, `size`, `radius` except an explicit allowlist of the exceptions that exist today (each with a one-word reason). The allowlist may only shrink later.
7. **Docs:** in `docs/design/03-DESIGN-SYSTEM.md` add the Figma size rule above as one short paragraph; status lines (<= 10) in `04-DESIGN-STATUS.md` / `11-PROJECT-STATUS.md`.

## Boundaries

- The only visual changes allowed are the size changes in step 3. Screens are untouched apart from the mechanical `figmaTokens` rename and fixes for newly reported lint violations.
- Do not demote or rename the ~133 tokens that have exactly one reader; do not clean all odd values at once.
- No new dependency, no new plugin.

## Done when

- `rg -n "figmaTokens" apps packages` -> empty.
- The "no dead tokens / no odd values" spec passes and fails if you add an unused token (say how you verified).
- `pnpm --filter @bidplace/mobile lint` green with the new rules and no `eslint-disable` added.
- Token count in `tokens.ts` decreased; nothing new was added except the allowlist inside the spec.
- Typecheck, vitest green. Playwright chromium for `figma-button-matrix`, `figma-text-field-focus`, `figma-stabilization` (or "not run: reason").
- Code `git diff --shortstat`: deletions >= additions.
- Report: deleted tokens, kept-dynamic tokens, changed expectations, "needs a node" list.

## Stop

A token with zero direct reads that is used dynamically (keep it, list it); a Figma size you cannot tie to a node; a lint rule that cannot be satisfied without a design decision.
