Это небольшой оставшийся хвост централизованного управления, а не основание переоткрывать всю миграцию. Фраза «все видимые цвета через useAppTheme» неверна, даже если grep designTokens.color пуст.

**Решение:** добавить по роли для report action, story toolbar border и home author fan shadow в существующий semantic contract (или использовать уже существующую роль только при совпадении назначения, не только hex). Вызовы получают значения из palette; чистый layout helper принимает palette либо хранит только геометрию. Light сохранить точно. Black остаётся provisional до дизайна. Технические mask/transparent и настоящие brand assets не инвертировать автоматически, оформить короткий список намеренных исключений. Не объединять reportColor с usernameTaken лишь из-за одинакового hex.

**Приёмка:** representative mounted/helper tests с заведомо отличающейся палитрой проверяют report text+icon, toolbar border, shadow; light-значения не изменены. Ограниченный поиск видимых литералов/CSS/SVG вместе с palette aliases — не только одного имени. Не создавать новый framework или массовую глобальную замену.

## TC-02 — P2: правило остановки не выполнено, несмотря на «план исчерпан»

В отчёте одновременно заявлены полное закрытие и Needs verification для настоящего browser zoom/увеличения текста. Выполнение очереди миграции — code complete, но не acceptance complete. У документа статуса общий Partial справедлив; его и надо сохранять в итоговом отчёте.

**Решение:** закончить одну ограниченную ручную/браузерную приёмку login: настоящий 200% browser zoom с подтверждением масштаба, отдельно увеличенный текст, доступность всех действий/ошибок/legal, прокрутка и отсутствие clipping. Проверить фактическое увеличение текста (вычисленный размер), не считать выбор настройки достаточным. 320 CSS px/reflow — отдельный сценарий; CSS zoom не заменяет реальный browser zoom. При отсутствии безопасного доступного управления браузером передать человеку короткую инструкцию, а не закрывать пункт автоматически.

**Приёмка:** способ, браузер, scale, viewport, actual font size, screenshots и результат записаны; неизвестное остаётся Needs verification. Live Figma/desktop/black решения отделить от функциональной robustness-проверки. Переход к подготовке следующего экрана возможен; тиражирование якобы полностью принятого эталона — нет до этого gate.

## TC-03 — P2 для статуса проверок: новые baseline failures нельзя смешивать со старыми зелёными suites

Дополнительный docs-only `a89fe26a` появился после указанного в сообщении HEAD и сообщает production build на 9201ddb3 clean. Повторять build лишь по причине старого отчёта не требуется. Но он также сообщает 6 passed / 5 failed в другом наборе Chromium E2E: admin-revision-moderation ×2, catalog-pagination ×2 (изоляция сидов), search-chrome (цвет #2457E6 vs #004DFF). Заявлено сравнение на base 982a0e00; здесь это сравнение не воспроизводилось.

Search-overlay 18/18 и work-media-lifecycle 2/2 не противоречат этим failures — это другие спеки. Предсуществование означает «не регрессия миграции», но не «все gates зелёные».

**Решение:** отдельная короткая запись по пяти failures: exact test name, команда/окружение, base/head assertion, владелец и следующий шаг. Для seed failures исправлять изоляцию fixture, не упрощать продуктовые проверки. Для search-chrome сначала установить правильную семантическую роль/визуальный контракт, затем исправить ожидание или owner; не менять golden ради зелёного результата. Повторять только упавшие сценарии после изменения.

**Приёмка:** актуальный отчёт различает приёмку миграции и release gate. Эти failures не требуют глобальной чистки и не запрещают подготовку следующего дизайна; поведение соответствующего экрана нельзя объявлять проверенным, пока его gate красный.

## Минимальный остаток и правило остановки

1. Один небольшой коммит **TC-01**: три роли/места, narrow tests, светлый вид сохранён, исключения явно перечислены. Никакой новой волны переделки всех screens.
2. Один приёмочный проход **TC-02**: реальный zoom + text enlargement. Если нужна ручная помощь — дать человеку шаги и записать результат; отсутствие такой проверки не маскировать словом «исчерпан».
3. **TC-03**: честный журнал известных красных gates; адресно починить fixture/контракт прежде чем считать затронутые сценарии проверенными. Не повторять весь E2E suite.
4. После новых code changes — релевантные typecheck/lint/tests; production build повторить только если новые runtime-правки меняют уже собранный SHA и нужен окончательный build artifact. Не повторять его ради docs-only изменений.
5. Закрыть техническую волну и перейти к **одному** выбранному экрану. Сначала intake актуального exact Figma node, mapping на существующие owners, responsive contract, затем код и measured evidence. Миграция цветов профиля автора ещё не означает, что композиция его блоков совпадает с Figma.

**Готовность: 8/10 по архитектурной подготовке, финальная визуальная приёмка пока Partial.** Основная чистка действительно завершена. Остаток — небольшой цветовой хвост и проверки, не переписывание половины проекта. Black theme остаётся provisional/NEEDS-FIGMA; централизованные роли позволяют доделать её без ручной перекраски экранов, но ещё нужны дизайнерские значения/контраст/проверка всех состояний.
