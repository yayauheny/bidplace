# Bidplace MVP Stabilization Audit

Date: 2026-07-16

## Scope

This pass used the original MVP audit plus the amendment set as input and implemented the stabilization plan in five bounded stages:

1. Prisma ownership and integration isolation
2. PostgreSQL `LotImage` storage and removal of filesystem uploads
3. Image access rules, limits, and seller image management API
4. Persistence typing cleanup and backend hardening
5. Critical integration coverage, mobile/query cleanup, and audit refresh

The goal of the pass was not to redesign the whole repository. The goal was to leave one clean, working implementation for each core system so new features can copy the current project patterns safely.

## Delivered Changes

### 1. Prisma ownership and integration isolation

- `@bidplace/database` now exports one generated Prisma surface: `PrismaClient`, `Prisma`, `Decimal`, and generated types.
- The shared package no longer owns a global Prisma instance.
- `apps/api` owns the connection lifecycle through `PrismaService`.
- Integration tests create their own `new PrismaClient()` from `@bidplace/database`.
- Integration bootstrap now requires `INTEGRATION_DATABASE_URL` to point to a test database name and creates a fresh schema with the `itest_` prefix per run.
- Integration schema setup uses migration history through `prisma migrate deploy`.
- Destructive schema cleanup refuses non-test targets.
- Runtime imports from `.pnpm` and alternate `@prisma/client` paths were removed from production and integration code.

### 2. Image storage migration to PostgreSQL

- Added `LotImage` as the single database source of truth for lot images.
- `LotImage` stores:
  - unpredictable UUID `id`
  - `lotId`
  - stable `position`
  - detected `mimeType`
  - `byteLength`
  - binary `data`
  - server-generated `checksum`
  - `createdAt`
- Schema guarantees:
  - index on `lotId`
  - uniqueness of `(lotId, position)`
  - cascade delete from `Lot`
- Public API still returns `images: string[]`, now backed by stable `/api/images/:imageId` URLs.
- Normal lot projections now select only image metadata needed for URL building; binary payload is not part of normal lot queries.
- Old local upload storage, static `/uploads`, upload directory management, local cleanup, and related env/config code were removed.

### 3. Upload validation, read rules, and image management

- Supported raster formats are explicitly limited to `jpeg`, `png`, `webp`, and `gif`.
- Upload validation checks file signatures instead of trusting only client MIME.
- Empty, corrupted, unsupported, and MIME-mismatched payloads are rejected before persistence.
- `svg` and base64 JSON uploads are not accepted in this pass.
- Configured lot image limits:
  - max files per lot: `8`
  - max bytes per image: `5 MiB`
  - max total bytes per lot: `40 MiB`
- Multipart limits are enforced at the Nest interceptor boundary.
- Added image response headers:
  - `Content-Type`
  - `Content-Length`
  - `ETag`
  - `Cache-Control`
  - `X-Content-Type-Options: nosniff`
- Access rules now follow lot visibility:
  - published public lot images are public
  - draft/unpublished images are available only to owner and admin
  - inaccessible image lookup returns a safe not-found response
- Added seller image management endpoints:
  - `DELETE /api/seller/lots/:lotId/images/:imageId`
  - `PATCH /api/seller/lots/:lotId/images/reorder`
- Image delete and reorder execute as short database transactions after validation.

### 4. Persistence typing and backend hardening

- Query typing now prefers local `select` ownership plus `Prisma.*GetPayload` where the result leaves a service boundary, feeds a mapper, or carries relations/sensitive fields.
- Mechanical `select` usage was avoided for write-only operations that do not consume the returned record.
- Removed widening patterns that hid real query shapes, including raw record casts in the main cleanup path.
- Auth persistence now has separate credentials and public user projections.
- Enum-like database strings continue to become contract values only after runtime parsing.
- Rate limiting remains in-memory for the current single-instance topology, but now includes:
  - lazy expired-entry cleanup
  - bounded periodic cleanup
  - `RATE_LIMIT_MAX_BUCKETS`
  - cleanup timer shutdown through Nest lifecycle
  - fake-timer tests
- `X-Forwarded-For` is only trusted when proxy trust is explicitly enabled.
- Socket emission stays outside the transaction callback and only happens after successful commit.
- `.env` resolution no longer depends on `process.cwd()`; it now supports:
  - explicit `BIDPLACE_ENV_FILE`
  - module-relative upward search that works from `src` and `dist`
- Sensitive runtime errors are no longer passed through as raw Prisma/storage internals.

### 5. Mobile/query cleanup and critical tests

- Added deterministic integration coverage for:
  - bid before start
  - seller self-bid
  - below-minimum bid
  - concurrent bids
  - close-vs-bid race
  - duplicate close
  - reserve met
  - reserve unmet
  - rollback on failed serializable transaction
- Added integration coverage for image flows:
  - draft image privacy
  - owner/admin draft access
  - image delete without orphan rows
  - image reorder with stable positions
  - lot delete cascade for images
  - normal lot projections remain free of binary payload
- No new concurrency tests use `sleep` or `setTimeout`.
- Mobile auth cache invalidation now removes only auth-scoped query segments instead of clearing all public data.
- Public category data is now keyed as public catalogue data instead of seller-private cache.
- `AuctionCard` and `AuctionGallery` now use `expo-image`.
- Relative and absolute image URLs continue to flow through one helper.
- Price/number formatters no longer allocate new `Intl.NumberFormat` instances during hot renders.

## Intentional Decisions and Non-Goals

- Old local image paths were treated as disposable local development data. No dual-source migration layer was kept.
- This pass did not add S3, Redis, outbox delivery, repository frameworks, or generic storage abstractions.
- This pass did not broaden into a general frontend redesign or new seller image UI.
- The current image read implementation returns database bytes in one response buffer. It is acceptable for the configured MVP limits, but it is not described as true database streaming.

## Remaining MVP Limitations

These are known and accepted for the current stage.

### PostgreSQL image storage cost

- The main database will grow faster than with object storage.
- Backups and restores will become heavier.
- API memory usage during image reads grows with payload size because Prisma materializes `Bytes`.
- Efficient CDN fan-out is still not available without a separate object-storage or caching layer.
- If image volume grows materially, the backend implementation should move behind the same public image URL contract to object storage.

### Realtime delivery semantics

- Socket emission now happens only after transaction commit, which removes the incorrect in-transaction pattern.
- The remaining MVP limitation is still real:
  - database commit can succeed and the process can crash before socket emission
- REST/refetch remains the source of truth; sockets are refresh signals, not exactly-once delivery.

### Rate limiting topology

- Rate limiting is guaranteed only inside one API instance.
- Horizontal scaling will require shared counters with TTL.

## Acceptance Checks

Passed in this stabilization pass:

- clean Prisma generation/build works after removing generated output
- integration bootstrap refuses non-test database URLs
- API and integration tests use the shared generated Prisma client surface
- no runtime imports remain from `.pnpm` Prisma paths in project code
- private and draft images are not publicly readable
- normal lot queries do not include binary image data
- upload limits and MIME/signature checks are enforced on the backend
- image delete and reorder do not leave orphan rows
- lot delete cascades image rows
- old local upload code was removed
- no parallel database source of truth remains for lot images
- Prisma transactions do not emit Socket.IO events from inside the transaction callback
- concurrency tests do not use timing sleeps
- no generic storage/repository/mapper framework was added

## Verification

The following checks passed in this pass:

- `pnpm lint`
- `pnpm typecheck`
- `pnpm --filter @bidplace/contracts test`
- `pnpm --filter @bidplace/api test`
- `pnpm test:integration`
- `pnpm build`

## Outcome

The repository is materially safer to extend than it was before the stabilization work:

- Prisma has one owned lifecycle boundary
- integration tests exercise the real migration path
- image handling has one storage model and one access model
- persistence typing no longer relies on routine unsafe casts
- mobile auth cache behavior no longer nukes unrelated public data

The current baseline is still intentionally MVP-sized, but the remaining shortcuts are explicit, bounded, and documented instead of being hidden behind patterns that look production-ready when they are not.
