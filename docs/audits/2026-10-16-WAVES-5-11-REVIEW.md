### W11-01 — P1 для приёмки: CSS zoom выдан за проверку browser zoom и доступности
`apps/mobile/e2e/login-figma-acceptance.spec.ts:100–113`: устанавливает documentElement.style.zoom='2', проверяет scrollWidth и только видимость submit в viewport. Это не проверка браузерного zoom, увеличения текста или доступности всех полей/ссылок. README утверждает отсутствие clipping без таких проверок.
Решение: сохранить CSS zoom только как дополнительную проверку с правильным названием; отдельно получить реальный browser zoom 200% и увеличение текста. При невозможности автоматизации — ручная проверка с evidence, честный Needs verification. На узкой/короткой области проверить прокруткой доступность полей, ошибок, основных действий и legal-ссылок, клавиатурный обход и возврат фокуса.
Критерий: реальные способ/масштаб/браузер записаны, screenshots приложены, каждое действие доступно; viewport resize не заменяет zoom.

### W11-02 — P2: отчёт утверждает больше, чем проверяет тест
`e2e/login-figma-acceptance.spec.ts:79–96` проверяет только горизонтальный overflow страницы и видимость контейнера. README пишет «нет вертикального overflow», «без clipping», «структура 1:1». Порядок и размеры элементов в тесте не измеряются. Вертикальная прокрутка сама по себе допустима и нужна на коротких экранах.
Решение: измерить bounding boxes ключевых элементов против nodes.json (sheet, title, fields, actions, divider, legal); отдельно проверить доступность содержимого внутри scroll-owner, а не отсутствие вертикальной прокрутки. Добавить таблицу expected/actual/delta/browser/state. Название теста должно соответствовать проверяемым гарантиям.
Критерий: таблица содержит фактические измерения и допустимые обоснованные расхождения; Partial сохраняется до проверки, не объявлять полное визуальное соответствие по числам токенов.

### W9-01 — P2, архитектура: общие примитивы ещё содержат собственную видимую палитру
`apps/mobile/src/components/figma/figma-chip-style.ts:7–10,21–33`: `figmaChipGradientStroke` хранит rgba белого/серого прямо в owner-helper. Для onDark/tinted функция возвращает этот объект независимо от переданной SemanticColorMap. Значит изменение темы/общих цветов не проходит через один token owner. Это общий компонент, а не отложенный экранный слой.
Решение: вынести два stop в семантические роли design-tokens, использовать palette во всех затронутых вариантах. Сохранить точные light-значения. Если роль должна оставаться постоянной поверх изображения — явно описать это и всё равно хранить значения в token owner. Не переносить технические цвета CSS mask (#000) в визуальную палитру: это не видимый цвет.
Критерий: тест с отличающейся палитрой проверяет оба stop, representative web/native consumer использует переданные значения, light визуально неизменен. Проверить аналогичные видимые литералы в общих owners ограниченным поиском, без массовой замены всех чисел.
