Исправления и повторный прогон тестов здесь не выполнялись.

## 1. Дубликат: явное сообщение

Пользователь просит прямо сообщать, что такое фото уже загружено.
На [снимке 1](01-duplicate-message.png) сейчас общий заголовок
«Не удалось выбрать фото» и пояснение «Это фото уже выбрано.».
Для ревью: различать уже выбранный локальный файл и уже загруженное фото,
показать понятную причину без общего вводящего в заблуждение заголовка.
Точная формулировка должна соответствовать фактическому состоянию файла.

## 2. Перетаскивание не работает

Прямое наблюдение пользователя: «перетаскивание фото вообще не работает».
Статичный кадр не подтверждает последовательность drag/drop. Нужны воспроизведение
в пользовательском Web-сценарии и запись движения мышью: старт с изображения,
смещение соседей, отпускание в свободный слот/промежуток, сохранение порядка,
отмена и выход за сетку. Прежние автоматизированные проверки не опровергают
пользовательское наблюдение. Последняя ручная попытка управления была
неубедительной; это уже отражено в [предыдущем отчёте](../2026-10-27-photo-manual/README.md).

## 3. Загрузка и видимая обратная связь

По наблюдению пользователя, фото начинает прогружаться только после нажатия
«Загрузить фото», состояние выглядит неясно; нет надписи о загрузке как в макете.
Ожидание: явное состояние «Загрузка» на карточке со спиннером по
[референсу пользователя — снимок 4](04-loading-reference.png).
Проверить отдельно локальное чтение/подготовку, сетевую загрузку и загрузку
изображения для отображения; установить, на каком этапе нет обратной связи.
Не подменять эти этапы одним недостоверным статусом и не предполагать причину
до воспроизведения. Последний кадр — визуальный референс, а не снимок текущего сбоя.

## Остальные предоставленные кадры и контекст

- [Снимок 2: низ страницы после отправки](02-submission-bottom.png).
- [Снимок 3: обзор страницы «Работа отправлена»](03-submission-overview.png).

Эти два кадра сохраняют контекст пользовательского прохождения и отображения
фото/истории после отправки. Текст ошибки обновления access token находится
внутри загруженного изображения; сам кадр не доказывает ошибку авторизации Bidplace.
Новые отдельные дефекты из этих кадров без запроса/воспроизведения не выводились.

На момент проверки Web8081 подключён к существующему тестовому API3017 и
изолированной E2E-базе. Тестовый media-server хранит объекты в памяти процесса:
старые записи базы могут ссылаться на отсутствующие файлы после перезапуска.
Основное демо API3001 — другое окружение. Это ограничение обязательно учитывать
при проверке появления фото и не смешивать с подтверждённой причиной дефекта.
